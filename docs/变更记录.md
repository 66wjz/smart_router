**现象**：用户把中转站接入 DSH 后，所有消息报

2. 直连生产号池 `127.0.0.1:8326` 逐项对比，`developer` 单独触发 400：
   `{"error":{"message":"unsupported message role: developer","type":"invalid_request_error"}}`

### rule 聚合的真实路由绑定（规则子集 + 候选子集）（B 线-大，本地实现未部署）

**背景**：CH-023 把「手写聚合名」统一成 `kind=rule` 的聚合实体，但**只统一了名字、没统一行为**——`get_ordered_candidates()` 签名里没有聚合名参数，所有 rule 聚合共用同一套全局规则和同一份候选，无法表达「这个聚合只要一部分模型」，探测成本也无法按聚合区分；且新增聚合时 `kind` 写死 `static`，前端无法创建 rule 聚合。

**变更内容**：

- **数据层**：`agg_unified` 新增 `rule_bindings` TEXT 列（增量 SQL 08），存 JSON 绑定，仅 `kind=rule` 有意义
