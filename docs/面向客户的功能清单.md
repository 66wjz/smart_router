面向客户的功能清单

创建时间：2026-08-09
版本：v5.2.3（2026-10-21）。沿革：v5.1（2026-08-11 修订：多分组权限、智能重试、透传查找已配置模型、仪表盘双视角、智能路由折叠菜单）；2026-10-16 增补：模型聚合可视化编辑、异名模型自动识别合并、单模型启停与拖拽排序、三层用量统计；后台导航重组为「智能路由 / 统计」分组，路由参数与热重载收拢至智能路由；2026-10-17 增补（CH-023）：聚合模型统一（固定成员 / 规则匹配同页管理）、探测模板、探测排班表、延迟面板与路由参数归位；2026-10-18 增补（CH-034/CH-036）：聚合独立分组、同名模型自动聚合默认关闭；2026-10-19 增补（CH-038）：请求详情三栏对比、缓存 token、重试链、断连记录、日志定期清理；2026-10-21 增补（CH-041）：请求过滤引擎（聚合无感切换 / 直连 400 + 用量页「已过滤」）

一：客户端用户端（AI 接口服务）

1.1 智能路由
1.1.1 统一模型名智能路由
功能详细描述：1.客户端使用一个固定模型名（如 smart-latest）调用接口即可，不需要关心底层用哪个模型。2.网关根据请求内容自动判断该走哪条路由：请求带图片走视觉理解规则，带工具调用走工具规则，普通对话走默认规则。3.每条规则内，网关结合各模型实时延迟和权重自动挑选最合适的模型。

1.1.2 上下文感知路由
功能详细描述：1.网关自动估算请求的字数规模，如果某个模型上下文装不下当前请求，会自动跳过它选择更大上下文的模型。2.请求的输出长度上限超过模型能力时，网关自动帮你调低，避免报错。

1.1.3 故障自动转移
功能详细描述：1.某个模型连续失败多次会自动进入冷却名单，暂时不再被选中。2.请求失败时网关会自动换下一个备选模型重试，无需客户端干预。3.流式对话中如果模型迟迟不响应，会自动切换到备用模型，避免长时间卡住。

1.2 模型别名（指针）
1.2.1 别名固定转发
功能详细描述：1.管理员给客户端分配一个固定的模型别名（如 my-model），客户端一直用它调用即可。2.管理员在后台切换别名指向哪个真实模型时，客户端完全无感，无需改任何配置。

1.3 直接透传
1.3.1 指定模型直连
功能详细描述：1.客户端可以直接指定某个具体模型名调用，网关会找到该模型所在的提供商并直接转发，不走智能路由也不重试。2.模型只要在某个上游源的"已配置模型"里登记过即可直连（2026-08-11 起），不必再加入路由规则。3.同名模型跨源自动兜底（2026-10-16 新增）：同一个模型名若分布在多个上游源，网关自动把它们互为候选，前一个源失败自动换下一个，客户端无感；管理员可在「聚合模型名」页查看并自定义参与聚合的源及其顺序，也可单独关闭某个模型的聚合。

1.3.2 智能重试（源级开关）
功能详细描述：1.付费/高可用源可开启智能重试：遇到 5xx、超时、连接中断时自动换一把 Key 或退避重试，客户端无感知。2.默认关闭，避免免费源触发不必要的重复扣费/限流。3.响应头带 X-Served-By（实际命中的上游和模型）与 X-Retry-Count（重试次数），方便排查。

1.4 协议兼容
1.4.1 多协议格式支持（2026-08-10 修订）
功能详细描述：1.客户端可用三种协议任意一种接入：OpenAI 格式（/v1/chat/completions）、Anthropic 格式（/v1/messages，Anthropic SDK 直接可用）、Responses 格式（/v1/responses，Codex 直接可用）。2.网关连接上游时同样支持三种协议，同一个上游源里每个模型可单独指定协议——像 opencode 这种"同站不同模型不同协议"的源，一个源就能全部接入。3.任意协议客户端可调用任意协议上游的模型，网关自动完成双向转换（含流式）。

1.4.2 兼容新 SDK 的消息角色（2026-10-19 CH-037 新增）
功能详细描述：1.OpenAI 新版把 `system` 角色改名为 `developer`，较新的客户端（如 DSH、新版 SDK）会把 `developer` 放在首条消息里。2.部分上游/中转只认 `system`，遇到 `developer` 会直接返回 400，导致该请求在所有候选上都失败、聚合整体报「所有模型均不可用」。3.网关在转发前自动把 `developer` 改写为 `system`（两者语义等价），客户端无需任何改动。4.只改角色，消息内容与顺序原样保留；其它角色（user / assistant / tool / system）完全不受影响。


1.5 访问鉴权
1.5.1 两层密钥保护
功能详细描述：1.客户端必须携带管理员分配的密钥才能访问，密钥无效或缺失会直接拒绝。2.密钥分为不同权限组（如免费组、付费组），付费组的密钥才能访问付费模型。3.网关访问模型提供商时使用提供商自己的密钥，客户端的密钥不会泄露给上游。

1.5.2 多分组权限（2026-08-11 新增）
功能详细描述：1.一把客户端密钥可以同时拥有多个分组的权限（如 free + premium）。2.一个上游源也可以同时归属多个分组——同一个源既给免费用户用也给付费用户用，只需勾选多个分组即可。3.判定规则：密钥的分组与源的分组有任意一个交集就能访问，否则拒绝。4.客户端拉取可用模型列表时，只会看到自己权限内的已配置模型。

二：管理员端（Web 管理后台）

2.1 登录与安全
2.1.1 后台登录认证
功能详细描述：1.管理员输入用户名密码登录，登录后获得访问令牌，默认 24 小时有效。2.未登录无法访问任何管理功能。

2.1.2 修改后台密码
功能详细描述：1.管理员可随时修改登录密码，需先验证当前密码，新密码至少 6 位，修改后立即生效。

2.2 仪表盘
2.2.1 系统概览（2026-08-11 双视角重设计）
功能详细描述：1.中转视角：上游源状态一览表（分组/模型数/Key 数/智能重试/启停）、API Key 数量与覆盖分组。2.路由视角：候选可用率、每条路由规则的候选健康度与最快延迟、聚合入口一览。3.看到当前哪些模型处于故障冷却状态。4.可一键热重载配置、刷新延迟数据、直达分组管理。5.侧边栏将"路由规则/聚合模型名/延迟面板"收进可折叠的「智能路由」菜单，与中转站基础职能区分开。

2.2.2 运营仪表盘（2026-10-17 重设计）
功能详细描述：1.顶部健康条一眼看全：探测是否开启、去重探测单元数与可用/不可用/未知分布、全局探测时段及当前时段外数量、近 7 天成功率、待关注数量。2.五张指标卡：今日请求（附「今日至今 vs 昨日同期」环比）、今日 Tokens、今日成功率、活跃 Key、聚合组（含源成员数与探测开启组数）。3.近 7 天用量趋势图：请求数与 Tokens 双指标折线，悬浮显示每天具体数值。4.上游源贡献占比：按 Tokens 排序的占比条，直观看出哪家额度吃得最多，附失败数。5.上游源卡片：状态点、分组、模型/Key 数、7 天请求与 Tokens、探测可用率、智能重试标记，禁用的源自动灰化。6.聚合组概览：每个聚合名的探测配置（开关/间隔/时段）、排序模式、成员链路、7 天用量一屏可见。7.「需要关注」区把冷却中、探测不可用、无可用 Key、数据陈旧、已禁用的源集中列出。8.指标卡和聚合组卡片可直接点击跳转到对应管理页。

2.3 密钥管理
2.3.1 客户端密钥管理
功能详细描述：1.查看所有客户端密钥及启用状态，密钥列表做脱敏显示。2.手动添加或随机生成新密钥。3.可随时启用、禁用或删除密钥，删除需二次确认。

2.4 上游源管理
2.4.1 上游源增删查
功能详细描述：1.查看已接入的模型提供商列表，包括名称、地址、协议格式、分组。2.添加新的模型提供商（填 ID、名称、地址、密钥、格式）。3.删除不再使用的上游源。

2.4.2 拉取模型列表
功能详细描述：1.一键从上游源拉取可用模型清单，方便后续配置路由。2.也可以手动输入模型名作为补充。

2.4.3 单模型启停与拖拽排序（2026-10-16 新增）
功能详细描述：1.上游源内每个模型可单独启用/禁用——禁用后不出现在客户端模型列表、不参与路由和延迟探测，适合屏蔽某家源里失效或不想用的模型，而不必整条删除。2.模型顺序可直接拖拽调整（拖动左侧手柄），调整后立即保存生效；顺序决定同名跨源聚合时优先走哪个源。3.模型较多时列表默认折叠，展开后可拖拽。

2.5 路由规则管理
2.5.1 规则可视化编辑
功能详细描述：1.查看现有路由规则及每个规则下的候选模型分组。2.可视化添加候选模型：选择上游源、选模型、设权重和优先级、设上下文限制。3.保存后立即生效。4.（CH-028）「选模型」为可筛选下拉，数据来自该上游源**已配置的模型**，不受上游是否可达影响；该源尚未配置模型时退化为手动输入。

2.5.2 规则 YAML 精细编辑（2026-10-18 CH-028 调整为卡片 + 弹窗）
功能详细描述：1.对熟悉配置的管理员，可直接编辑规则源码（JSON 格式），更精细灵活。2.规则页底部以独立卡片只读展示当前源码，超出区域可滚动。3.点卡片右上角「修改」弹出大窗口编辑，保存时自动校验格式，格式错误会提示且不关闭窗口。4.弹窗内「重新加载」可丢弃未保存的编辑、恢复为当前已保存内容。

2.6 模型别名管理
2.6.1 别名增删改查
功能详细描述：1.查看所有模型别名及它们当前指向的真实模型。2.添加新别名、删除旧别名。3.随时修改某个别名指向哪个模型和哪个提供商。

2.7 探测与延迟（2026-10-17 CH-023 调整）
2.7.1 延迟与健康状态查看
功能详细描述：1.查看每个模型的实时延迟和状态（可用、不可用、未知）。2.查看每条路由规则内各候选模型的动态权重和延迟表现。3.（CH-023）原「延迟面板」独立页已并入「智能路由 → 聚合模型 → 探测计划」，旧地址 `/latency` 自动跳转；告警与冷却状态在仪表盘与探测单元明细中展示。

2.8 聚合模型管理（2026-10-17 CH-023 统一 · CH-024 规则绑定）
2.8.1 两类聚合统一管理
功能详细描述：1.聚合分两类，都在同一个列表里管理：**固定成员**（自己勾选哪些源、哪个真实模型，支持异名，按顺序跨源兜底）与**规则聚合**（候选由「路由规则」页在运行时按请求内容匹配，例如带图走视觉规则、带工具走工具规则）。2.固定成员可编辑成员、拖拽优先级、指定该源真实模型名、单独关闭；规则聚合不能配成员，可在同一弹窗里选择「规则匹配」类型。3.（CH-024）**规则聚合可裁剪**：新增/编辑聚合时可选「用哪几条规则」「每条规则用哪几个候选」——规则全选即「跟随」（以后规则加模型会自动纳入），取消任一候选则存显式子集。一张规则表 + 每个聚合引用其子集。4.（CH-024）规则页删除/改名规则 → 自动清理引用它的聚合绑定，清理后为空回退全跟随；规则页移除某候选 → 聚合卡片显示黄色「N 个候选已失效」提示（运行时静默跳过）。5.徽标区分「固定成员 / 规则匹配」「手动配置 / 自动发现」「模板: xxx」「稳定优先 / 速度优先」「探测: 开 · xx s · 限时段」，规则聚合额外显示绑定摘要「N 条规则 · M 个候选」。6.每个规则聚合的探测对象 = 其绑定裁剪后的候选并集，因此不同规则聚合的探测成本可以不一样。

2.8.1.1 新建聚合时选择类型（2026-10-17 新增）
功能详细描述：1.新建/编辑聚合弹窗顶部有「聚合类型」单选：固定成员 / 规则匹配。2.选「规则匹配」后主体切换为绑定编辑器：每条规则一张卡片，勾选「使用」即纳入本聚合，卡片内可逐条勾选候选（显示上游源 · 真实模型 · 优先级 · 权重），也可点「全选」跟随整条规则。3.取消所有规则的「使用」会被阻止并提示「至少保留一条规则」；规则页还没配候选时提示先去做规则。

2.8.2 探测模板（2026-10-17 新增）
功能详细描述：1.模板 = 一套可复用的探测节奏（间隔、慢阈值、排序方式、探测时段）。2.多个聚合挂同一模板后共用同一节奏——改模板一次，所有引用它的聚合立即生效，不用逐个重复配置。3.挂模板后聚合自己的探测参数被模板完全覆盖（不可被组覆盖），界面上对应输入框置灰并提示「由模板决定」。4.模板列表显示被多少个聚合引用、分别是谁；删除模板前会提示影响范围，删除后引用方回退到自配参数，再没有则跟随全局。

2.8.3 探测排班表（2026-10-17 新增）
功能详细描述：1.用排班表的形式直观展示每个探测单元在 0~23 点是否探测：蓝色块 = 探测中、灰块 = 时段外、斜纹 = 探测已关闭。2.支持「合并视图 / 按星期」切换，按星期视图逐行展示周一到周日。3.每行给出探测间隔、次/时、次/日与引用它的聚合名（规则聚合用紫色标注），一眼看出成本是被谁拉高的。4.表头汇总「N 个探测单元 · 去重省 M 次 · 每天约 X 次请求 · 覆盖 P 个聚合」。5.规则聚合的探测对象 = 该聚合绑定裁剪后的候选并集（CH-024；未配绑定时为全部规则候选并集）。

2.8.4 模型聚合可视化与编辑（2026-10-16 新增，CH-023 并入统一列表）
功能详细描述：1.用「1 源·真实模型 → 2 源·真实模型」的链路条直观展示，一眼看清某个聚合名背后挂了哪几个源的哪个模型。2.点击「编辑成员」可勾选/添加成员、为每个成员指定该源里的真实模型名、拖拽调整优先级、设置单源权重。3.每个聚合可单独关闭（退化为只走首选成员），也可一键「恢复自动」回到系统自动发现。4.未手动编辑过的同名模型零配置即可用。

2.8.5 异名模型自动识别与合并（2026-10-16 新增）
功能详细描述：1.同一模型在不同提供商那里名字往往不同——比如 `buddy/deepseek-v4.1-flash`、`loomy/DeepSeek-V4.1-Flash`、`trae/deepseek-v4.1-flash`，前缀、大小写、分隔符都不一样。2.系统会自动识别这类"疑似同一模型"（去前缀、忽略大小写、忽略 . 和 _ 的差异），在聚合页顶部列出建议分组。3.点「一键合并」即可合成一个聚合名（如 `deepseek-v4-1-flash`），客户端请求这个名字时按顺序跨源兜底。4.合并后仍可手动增删成员或调整顺序；不想合并的可以忽略建议。5.也可以完全手动「新建聚合」，任意组合不同源的模型。

2.8.6 聚合名在客户端模型列表可见（2026-10-18 CH-033 修复）
功能详细描述：1.聚合模型（无论「固定成员」还是「规则聚合」）现在都会出现在客户端拉取的模型列表里，并标注为聚合类型。此前固定成员聚合（尤其是异名聚合）虽然在路由上可用，但客户端拉不到它的名字。2.已关闭的聚合不会出现在列表中。3.聚合名与真实模型重名时只显示一次。

2.8.7 聚合独立探测与智能排序（2026-10-17 新增）
功能详细描述：1.每个聚合可单独开启/关闭定时探测，并各自设置探测间隔、慢阈值、排序方式——不同模型可以有不同的节奏，互不干扰。2.排序两档可选：「稳定优先」按你拖拽的顺序，只把超时/超慢/冷却中的成员沉到后面；「速度优先」直接按实时延迟从快到慢排。3.所有成员都不可用时按你配置的顺序兜底尝试，不会因为探测失败而导致请求直接报错。4.探测对象全局去重：每个「上游源 × 真实模型」只探一次，多个聚合共用同一模型不会重复探测。5.留空即跟随全局参数，改全局一次全生效。6.规则聚合仍沿用「优先级 + 动态权重（`base_weight × (base_latency/latency)²`）」排序，探测结果直接参与权重计算。

2.8.7 探测时段（2026-10-17 新增）
功能详细描述：1.不想夜里或周末浪费额度时，可以把探测限定在指定时段：全天候，或按「星期 + 时间段」组合（支持跨夜，如 23:00→07:00）。2.提供三个快捷模板：工作日全天、每天 08:00-23:00、仅周末。3.时段外自动停止探测，但保留最后一次延迟结果，面板上标记「时段外」，超过 3 倍间隔未更新则标记「数据陈旧」，不会误导判断。4.同一模型被多个聚合引用时，只要有一组处于探测时段内就会继续探测。

2.8.8 聚合列表拖拽排序（2026-10-18 CH-028 新增）
功能详细描述：1.聚合模型列表每张卡片标题左侧有拖拽手柄（⠿），按住可上下拖动调整聚合的展示顺序。2.松手即保存，刷新页面后顺序保持。3.自动发现（未手动配置）的聚合也能一起排序。4.新出现的聚合默认排在末尾，不影响已排好的顺序。5.顺序存在系统设置里，不改数据库表结构；不拖拽时保持系统默认顺序（先固定成员、再规则聚合，组内按名称）。

2.8.9 聚合模型独立分组（2026-10-18 CH-034 新增）
功能详细描述：1.聚合模型现在有自己的「可用分组」，与它内部用到的模型完全隔离——聚合自己配成什么分组，就只有这些分组的 API Key 能用它。2.典型场景：把某个提供商的所有模型放进「禁止单独使用」分组（防止绕过聚合直接调用），再建一个聚合、分组设为「免费」，这样免费用户只能通过聚合用它，不能直接点名调用。3.不选分组 = 所有 Key 都可用（升级后老聚合保持原有行为，不受影响）。4.固定成员聚合与规则聚合的规则完全一致。5.聚合卡片上会显示「分组: xxx」或「所有分组可用」徽标；编辑弹窗里的提示会说明「成员分组不再参与校验」。6.直接请求真实模型名时，仍然照旧按该模型所属提供商的分组判断权限——本次改动只放开聚合这一层。7.删除分组时，若该分组仍被聚合引用会被拦住并提示先解除引用。

2.8.10 同名模型自动聚合开关（2026-10-18 CH-036 新增）
功能详细描述：1.系统设置新增「同名模型聚合」开关，默认**关闭**。2.关闭时：多个源都有同名模型只做跨源兜底（一个源失败自动换下一个），不会凭空出现在聚合列表里，也不会被当成聚合参与分组权限判断——需聚合请在「聚合模型」页手动创建。3.打开时恢复旧行为：同名模型分布在 ≥2 个启用源时自动成为聚合组。4.老库升级会一次性把该开关置为关闭（只改一次，之后你手动打开不会被重启覆盖）。5.升级同时清理历史上因「移除自动发现聚合」而遗留的空壳配置行，让这些模型恢复正常跨源兜底。

2.9 用量统计（2026-10-16 新增）
2.9.1 三层用量统计
功能详细描述：1.全局层：请求总数、总 tokens、成功率、活跃 Key 数、高频错误 Top5，支持今日 / 近 7 天 / 近 30 天切换。2.模型层：每个模型的请求数、错误数、prompt/completion/总 tokens、平均耗时、涉及源数。3.客户端 Key 层：每把 Key 的请求数、错误数、总 tokens、平均耗时。4.明细层：最近请求逐条记录（时间/Key/模型/上游源/协议/流式/状态/tokens/耗时/错误摘要），支持按状态和模型过滤、分页。5.失败请求同样记录，成功率真实可信；上游未返回用量时自动按字符估算并标注"估算"。6.记录默认保留 14 天（可设 7/14/30/90），主表与详情表同步自动清理。

2.9.2 按单元用量（号池核算，2026-10-17 新增）
功能详细描述：1.除"按模型""按 Key"之外，新增「按单元（上游源 × 真实模型）」统计——聚合请求会记账到实际命中的上游真实模型名，而不是客户端请求的聚合名。2.这解决了一个关键问题：请求 `deepseek-v4-1-flash` 时可能命中 buddy 或 loomy 的真实模型，只有按真实模型名统计才能看出各家额度实际消耗多少。3.显示请求数、错误数、总 tokens、被多少个不同请求名命中、平均耗时，为后续按积分余额自动停用某些模型打基础。

2.10 系统设置
2.10.1 全局容错（2026-10-17 CH-023 归位）
功能详细描述：1.请求重试（最大尝试次数 / 响应超时 / 首包超时）、智能重试（额外次数 / 退避间隔 / 抖动）、故障转移（最大连续失败 / 冷却时间）三组参数统一放在「系统设置 → 全局容错」。2.这些参数对所有请求生效（规则聚合、固定成员聚合、直接透传、别名都一样），与具体聚合无关，因此不再放在「路由参数」页。3.原「路由参数」页已移除，`/route-params` 自动跳转到系统设置。

2.10.2 全局探测默认值（2026-10-17 CH-023 归位）
功能详细描述：1.配置延迟探测的开关、探测间隔、超时时间、不可用阈值、基准延迟、慢阈值、探测并发数、探测失败是否计入 Key 冷却、全局探测时段。2.该区块现位于「智能路由 → 聚合模型 → 探测计划」标签页底部——它只决定「没挂模板、也没自配的聚合怎么探」，不决定「探哪些」。3.（2026-10-17 新增）探测失败默认不计入 Key 冷却，避免探测超时把唯一 Key 打进冷却导致真实请求失败。

2.10.3 配置热重载
功能详细描述：1.各参数保存时自动热重载；如需手动重载全部配置，可在「系统设置 → 配置操作」中操作。（2026-10-16 起顶栏全局热重载按钮已移除；CH-023 起「路由参数」页已并入其他位置）

2.10.4 运行日志与请求追踪（2026-10-18 新增）
功能详细描述：1.每次客户端请求都会记一行访问日志，包含：状态码、耗时、客户端 IP、请求的模型名、是否流式、消息条数；出错时（4xx/5xx）额外附上请求体摘要，方便事后追查"客户端到底发了什么"。2.请求体摘要最多 300 字符，其中的 `sk-` 开头密钥会自动打码成 `sk-abcd****`，不会把凭据写进日志。3.日志同时写到控制台和轮转文件（`logs/smart-router.log`，单文件 10MB、保留 5 份，不会无限增长）。4.管理接口 `GET /admin/api/logs` 可直接读取日志尾部（支持按关键词过滤，如只看 `status=500` 或 `ERROR`），不用登录服务器也能拿到现场。5.请求体不是合法 JSON 时，日志会明确标注 `body=INVALID(bad_json)` 并记录原始内容摘要，不再出现"只知道崩了、不知道为什么崩"的情况。

2.10.5 请求详情与断连记录（2026-10-19 CH-038 新增）
功能详细描述：1.用量页「最近请求明细」的每一行都可以点开，弹出三栏对比：**REQUEST（客户端原始请求）/ FORWARDED（我们实际发给上游的报文）/ RESPONSE（上游返回的响应）**——排查时一眼就能看清是客户端问题、网关改写还是上游问题。2.顶部摘要显示状态、时间、耗时与首包耗时、输入 / 缓存读 / 输出 token、模型、上游、Key、HTTP 码；下方「尝试链路」列出本次试过哪几个候选、各自 HTTP 码与耗时、失败原因。3.列表页 Tokens 改成「输入 / 缓存 / 输出」三段式，新增「尝试」列（>1 次标黄），一眼看出哪些请求发生了重试。4.存储按结果分档：成功请求只记结构化字段和 token，失败请求才保存完整报文——既省空间又保留最有价值的现场。可在「系统设置 → 用量与日志」切换为「全部请求」或「关闭」。5.单条报文默认上限 1 MB，超出时保留头 3/4 + 尾 1/4 并标注被截断的字节数。6.日志保留期默认 14 天（可设 7/14/30/90），主表与详情表每轮同步清理，不会留孤儿数据。7.报文落库前统一脱敏，`sk-` 凭据打码，请求头只留 UA/Content-Type/Accept 等排查必需字段。8.客户端在响应开始前断开连接时，日志会记一条 `status=499 disconnected=true`——此前这类请求完全没有任何痕迹，容易被误判成"请求没来过"。9.缓存 token 自动识别三种上游命名（OpenAI / Anthropic / 部分中转站），取不到时记 0 而不估算。10.必须知道边界：如果客户端在**连接建立阶段**就失败（如报 `error sending request`），服务端收不到任何字节，任何日志方案都记不到，只能从客户端侧排查。

2.10.6 请求过滤引擎（2026-10-21 CH-041 新增）
功能详细描述：1.用途是保护号池：上游渠道对某些「非官方客户端」有黑名单，别人反复用这类客户端打同一个源，会让号池里的号被上游封掉。开启过滤后，命中规则的请求**根本不会发出去**。2.规则可匹配三种对象：system 首行文本、全部 system/developer 文本、整个请求体正则；文本类按「包含」判定（宁可多拦，不漏拦）。3.动作二选一：「跳过」= 静默换下一个候选；「拒绝」= 直接返回 400。4.作用域可绑定一个或多个上游源，留空表示全部源。**重要**：预置规则的作用源限定为 `buddy` + `workbuddy`，因为实测只有这两个渠道会拦 DSH / Claude Code 的身份声明，其他渠道是放行的；若留空，放行渠道也会被一起拦掉，聚合候选被清空后客户端会拿到 503，而不是预期的「无感换成员」。发现新的拦截渠道时，在页面上把该源加进作用源即可。5.路由语义：**聚合模型无感切换**——命中的成员被移除，继续用剩下的候选，客户端完全感觉不到；只有全部候选都被拦才报错。**单独使用某个模型时直接返回 400**，回执写明命中了哪条规则、正在保护哪个上游源。6.全局开关默认关闭，关闭时不抽文本、不跑正则，零开销。7.预置「DSH 身份声明」「Claude Code 身份声明」两条规则，默认不启用，需要时手动打开。8.后台「请求过滤」页支持粘贴一段请求体试跑，直接看到哪些候选会被拦、命中哪条规则，不影响线上流量。9.被拦请求照常记进用量表，`error_msg` 带「已过滤」前缀，用量页有「已过滤」统计卡片与筛选项；详情里的尝试链把这些候选标为「未发送」。

客户端侧

3.1 智能重试（源级开关）
功能详细描述：1.不稳定的上游源（如 opencode 免费档）开启"智能重试"后，请求遇到 5xx 错误、超时、连接中断时，网关自动换该源的另一把密钥重试，或稍等片刻用同一把密钥再试，客户端完全无感知。2.重试次数和等待间隔可在系统设置里调。3.响应头会带 X-Served-By（实际走了哪个源）和 X-Retry-Count（重试了几次），方便排查。

3.2 分组权限过滤
功能详细描述：1.客户端查询模型列表（GET /v1/models）时，只能看到自己密钥所属分组的模型，无权分组的模型不可见也不可用。

管理侧

3.3 上游源启用/禁用
功能详细描述：1.上游源可一键禁用/启用，禁用后不再参与路由、探测和透传，配置保留。

3.4 上游密钥池（多 Key）
功能详细描述：1.每个上游源可粘贴多把密钥（每行一把），请求自动轮询分摊流量。2.某把密钥失败或被限流时自动换下一把，连续失败的密钥进入冷却，恢复后自动加回。

3.5 上游模型管理
功能详细描述：1.每个上游源下可维护"已配置模型"列表：一键拉取上游模型勾选加入、手动添加、单个/批量删除。2.每个模型可在线测试（单测/全量测/批量测），失败原因具体展示（状态码+上游错误原文）。3.每个模型可单独选择协议（继承源默认 / openai / anthropic / responses）。

3.6 可配置分组
功能详细描述：1.系统设置页可增删改分组（如 free / premium / 自定义）。2.上游源和密钥的分组下拉自动跟随。3.被上游源或密钥引用的分组不可删除，防止误删导致权限错乱。

3.7 接入体验
功能详细描述：1.添加/编辑上游源时，Base URL 下方实时显示最终拼接的请求地址和模型列表地址，不再靠猜。2.每个客户端密钥内置「接入说明」弹窗：请求地址、密钥一键复制、该密钥可用的模型清单、可直接运行的 curl 和 Python SDK 示例。
