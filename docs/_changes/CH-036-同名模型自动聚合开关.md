# CH-036 同名模型自动聚合开关（默认关闭）+ CH-033 / CH-034 收尾

> 类型：B 线-中（行为默认值变更 + 前端开关） + A 线（残留数据清理）
> 状态：已实现，已部署生产 10.10.0.2（2026-10-18）
> 日期：2026-10-18
> 来源：需求规格 9.1「同名模型自动聚合的全局开关」（CH-019 遗留承诺，`auto_same_name_enabled()` 写了但全仓 0 调用点）

---

## 一、背景

用户拓扑已变化：`dsh` 与 10 个按提供商拆分的上游源**共用同一个 `base_url` 与同一份 `api_key`**（同一号池）。分源的目的是「按提供商划分模型 + 分别配分组」，不是真的多家供应商。

因此「同名模型跨源自动聚合」**零收益**（背后同一后端，一个挂全挂），却持续制造问题：

1. **CH-033**：凭空冒出 4 条「自动发现」聚合，点「移除」报错（表里没有行）
2. **CH-034**：聚合名同时是真实模型名，系统分不清「门面」还是「普通模型」，权限语义产生歧义
3. 探测计划与仪表盘聚合组概览出现统计噪音

根因：CH-019 承诺的开关只写了读取方法（`config_upstream.py::auto_same_name_enabled`），**从未被任何代码调用**，设置页也无入口。

## 二、分类（铁律 7）

| 项 | 分类 | 说明 |
|---|---|---|
| 自动聚合开关缺失 | **B 线-中** | 新增配置项 + 前端入口 + 改变默认行为 |
| CH-033 残留：`enabled=false` 且成员为空的 static 行 | **A 线** | CH-033 为「移除自动发现聚合」落库的关闭行，开关关闭后已无意义；且它们会进入 `_model_groups`，使同名模型退化为单源直连（跨源兜底丢失） |
| CH-034 补充 | **A 线** | 开关关闭后自动发现不再出现在 `collect_group_members()`，CH-034 的「自动发现不算门面」防御性判断保留（开关打开时仍需要） |

## 三、设计

### 3.1 语义

| 开关 | `collect_group_members()` | `is_model_group()` | 裸模型名请求 |
|---|---|---|---|
| **关（新默认）** | 只返回**显式配置**的 static 聚合 | 只认显式聚合 | 仍跨源多候选兜底（`collect_model_upstreams()` 另一条路径，不受影响） |
| 开（旧行为） | 显式聚合 + 同名自动发现（≥2 个启用源） | 同名 ≥2 源也算聚合组 | 同上，且被当作聚合组走分层排序 |

> 关键：**关闭只影响「是否被当成聚合」，不影响「跨源兜底」**。同名模型在两个源都有时，`direct` 分支仍会返回 2 个候选。

### 3.2 数据

新增 `sql/increment/10_增量_20261018_自动聚合开关默认关闭.sql`：

1. `sys_setting.auto_same_name_aggregate` 缺行 → 插入 `false`
2. 存量值为 `true` → 翻为 `false`，**仅执行一次**（用 `auto_same_name_migrated_v2` 标记防重复，避免每次重启把用户手动打开的开关又关掉）
3. 清理 CH-033 残留：删除 `agg_unified` 中 `kind='static'` + `enabled=0` + `members='[]'` + `remark='已关闭（原自动发现聚合）'` 的行

### 3.3 代码

- `config_upstream.py::auto_same_name_enabled()` 缺省值 `True` → `False`
- `config_probe_plan.py::collect_group_members()`：`else` 分支先判开关，关闭则跳过自动发现
- `config_probe_plan.py::is_model_group()`：显式聚合之后先判开关，关闭直接返回 `False`
- `api/admin/config.py`：新增 `GET/PUT /admin/api/config/auto-aggregate`
- `services/config_service.py`：`get_auto_aggregate()` / `set_auto_aggregate()`
- `core/config_aggregation.py::sync_unified_tables()`：脚本清单追加 10（幂等：标记键 + 精确 DELETE）
- `backend/seed.py`：`SQL_FILES` 追加 10

### 3.4 前端

- `api/settings.ts`：`getAutoAggregateConfig` / `saveAutoAggregateConfig`
- `views/Settings.vue`：新增「同名模型聚合」区块 + 开关 + 说明文案

### 3.5 CH-033 / CH-034 收尾

- CH-033：残留关闭行由 SQL 10 清理；`delete_aggregation()` 的自动发现兜底分支保留（开关打开时仍需要）
- CH-034：`is_static_aggregation()` 的「自动发现不算门面」判断保留（开关打开时仍是必要的安全边界）；开关关闭后该分支自然不命中

## 五、验收标准

1. **默认关闭**：新建/升级库，`auto_same_name_aggregate=false`；聚合列表无「自动发现」卡片
2. **跨源兜底不受影响**：同名模型在 2 个源都有时，请求该裸模型名仍返回 2 个候选
3. **显式聚合正常**：手动保存的 static / rule 聚合照常工作，权限按 CH-034 门面语义
4. **打开开关恢复旧行为**：`PUT /config/auto-aggregate {enabled:true}` 后自动发现聚合重新出现
5. **标记幂等**：重启服务不会把用户手动打开的开关重置
6. **CH-033 残留清理**：`remark='已关闭（原自动发现聚合）'` 的空行被删除，同名模型恢复跨源兜底
7. **CH-034 回归**：门面权限矩阵全部通过
8. **回归**：CH-023 / CH-024 三套脚本全通过；`compileall` 0 错误；`npm run build` 通过

## 六、风险与回退

| 风险 | 影响 | 缓解 |
|---|---|---|
| 默认关闭导致「同名跨源兜底被误以为消失」 | 用户误解 | 文档与 UI 明确：关闭只影响「是否算聚合」，不影响跨源兜底 |
| 存量 `true` 被强改为 `false` | 用户原本依赖自动聚合 | 标记键保证只翻一次；用户可在设置页一键打开 |
| 清理的行误删用户配置 | 数据丢失 | DELETE 条件极其精确（空成员 + 特定 remark + 已关闭） |

回退：`git revert`；数据库新增/删除仅涉及 `sys_setting` 两键与 CH-033 残留行。
