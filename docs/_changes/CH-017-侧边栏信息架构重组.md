# 变更：管理后台侧边栏信息架构重组（按职能分组）

> 编号：CH-017
> 日期：2026-08-11
> 分类：B 线-小（纯前端导航调整，无 API 变更）
> 状态：方案待确认

---

## 一、变更背景

系统定位已从"聚合路由器"扩展为"中转站 + 聚合路由"双职能。当前侧边栏 8 个一级项平铺，其中**路由规则 / 聚合模型名 / 延迟面板**三项只服务于"聚合路由"职能（延迟探测只覆盖路由规则候选模型），与"API Key 管理、上游源管理"这类中转站基础职能并列，容易误导用户以为全系统都围绕聚合模型工作。

## 二、方案（2026-08-11 按用户意见修订）

### 2.1 导航结构（用户确认版）

不加"接入"分组，原有项保持一级平铺，**只新增"智能路由"分组**收编三个聚合职能页面：

```
仪表盘
API Key 管理
上游源管理
模型别名
── 智能路由 ──        ← el-menu-item-group 分组标题（不可点击）
  路由规则
  聚合模型名
  延迟面板
系统设置
```

- 菜单项仍全部一级直达，不引入折叠交互
- 延迟面板顶部加一行说明文案："延迟探测仅覆盖路由规则中的候选模型"

### 2.2 仪表盘重新设计（双职能视角）

设计稿：`docs/designs/CH-017-仪表盘设计稿.html`（静态 HTML，浏览器打开预览）

- **指标卡 4 张**：中转视角 2 张（上游源：启用数/模型数/Key 数；API Key：数量/覆盖分组）+ 路由视角 2 张（候选可用率；当前最快候选及延迟）
- **左栏「上游源状态一览」表**（中转视角）：每个源的分组/模型数/Key 数/智能重试/启用状态
- **右栏「智能路由概览」**（路由视角）：每条规则的候选数/可用数/最快延迟 + 聚合入口 chips
- **保留现有**：故障状态列表 + 快速操作（热重载/刷新延迟），快速操作加"分组管理"入口
- 标签体系：中转=蓝色标、路由=绿色标，视觉上区分两个职能

### 2.3 数据来源（全部现成，零后端改动）

仪表盘已有 `/admin/api/dashboard` + 前端另行组装：`/admin/api/upstreams`（源状态表）、`/admin/api/rules`（规则概览）、`/status`（延迟数据）、`/admin/api/aggregated-names`。不发明没有数据来源的指标（请求量统计等本期不做）。

### 2.4 影响面

| 层 | 位置 | 改动 |
|----|------|------|
| 前端 | `layouts/AdminLayout.vue` | 菜单加"智能路由"分组标题 |
| 前端 | `views/Dashboard.vue` | 按设计稿重写 |
| 前端 | `views/Latency.vue` | 顶部说明文案一行 |

无 API/DB 变更，无权限语义变更。
