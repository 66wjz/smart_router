# CH-042 列表页二级组件体系（ListPage / DataTable / FilterBar / TablePagination）

> 类型：B 线-大（新增组件层 + 新页面骨架 + 导出端点，前端为主）
> 状态：样例第二轮完成（工具条常驻 + 灰底 + xlsx 导出），待用户确认效果
> 日期：2026-10-21
> 来源：用户反馈「单个页面看还行，整体看乱糟糟；列表各做各的样式，没有章法；一级基础组件有了，缺列表这种二级组件」
> FB 编号：FB-034

---

## 一、要解决什么问题

### 1.1 现象

13 处列表各写各的：

| 维度 | 现状 |
|---|---|
| `el-table` 直接使用 | 13 处，`size`/`stripe`/`border` 各自决定（Rules 用了 `border`，其余没有） |
| 分页 | 只有 Usage 的请求明细有；其余 12 个列表全量渲染 |
| 搜索区 | 只有 Usage 有（`.log-filters` 私有样式） |
| 批量操作 | ApiKeys 没有；ModelList 自己写了 `model-batch-bar` |
| 空态 | `BaseEmptyState` / `.model-empty` / `.empty-tip` / `.muted` 四种写法 |
| 指标卡 | Dashboard `.metric-card/.mc-*` 与 Usage `.metric-*` 两份 |
| 按钮组 | `.row-actions` / `.rule-actions` / `.upstream-actions` / `.model-ops` / `.batch-ops` 五套 |
| 圆角 | 29 处声明，`8px` 与 `10px` 混用，只有部分走 `--radius-md` |

### 1.2 根因

1. **封装对象错了**：按「组件库该有什么」封装，不是按「页面里反复在写什么」封装。22 个基础组件里 6 个零引用（BaseTable / BaseSelect / BaseAlert / BaseSpinner / BaseAvatar / BaseCalendarPicker），而每天都在写的「搜索 + 工具条 + 表格 + 分页」从没被封过。
2. **缺组合契约**：`BaseSection` 只管到「标题 + 右上按钮 + 内容」，内容区怎么排没有约束。
3. **约定靠文档不靠组件**：`components/base/README.md` 写了「优先用基础组件」，但没有机制阻止直接写 `<el-table>`。CH-027 能把按钮统一，是因为只有一处；列表涉及 13 处 × 5 个要素，靠自觉必然漂。

### 1.3 目标

把「列表页」这个模式固化成一个组件：以后新页面只有一种写法，不走组件就得手写 5 段重复代码，天然劝退。

## 三、设计：缺的那一层

```
一级（已有 22 个）        二级（本轮新增）              解决的问题
BaseButton            →  ┌ FilterBar            搜索区：字段 + 查询/重置
BaseInput                ├ ListToolbar          批量区：已选计数 + 批量按钮
BaseBadge                ├ DataTable            表格：列配置 / 统一空态 / 加载 / 选择
BaseEmptyState           ├ TablePagination      分页：总数 + 每页条数 + 跳页
BaseSection              ├ StatCard             指标卡：label/value/tone/hint
BaseModal                ├ RowActions           行内操作组：统一间距
                         └ ListPage             骨架：上面各件的组合
```

### 3.1 组件职责边界

| 组件 | 做什么 | 不做什么 |
|---|---|---|
| `ListPage` | 列表页骨架：标题 / 描述 / 右上主操作 / 筛选区 / 批量区 / 表格区 / 分页区，统一垂直节奏 | 不管数据获取，不管业务逻辑 |
| `FilterBar` | 筛选字段容器 + 查询/重置按钮 + 回车触发 | 不定义具体字段（用 slot 传入） |
| `ListToolbar` | 已选计数 + 批量按钮区，`selectedCount === 0` 时自动隐藏 | 不管理选择状态 |
| `DataTable` | 包 `el-table`：columns 配置、加载态、空态、多选、行点击、slot 透传 | 不自研表格内核 |
| `TablePagination` | `共 N 条 / 每页条数 / 页码 / 跳页` | 不管数据切片 |
| `StatCard` | 指标卡：标签 / 数值 / 语义色 / 说明 | 不做图表 |
| `RowActions` | 行内按钮组统一间距与分隔 | 不定义按钮语义 |

### 3.2 复用原则（防止再造一套）

- 全部基于**现有** `BaseButton` / `BaseBadge` / `BaseEmptyState` / `BaseInput` / `BaseSection` / `BaseIcon` 组合，**不重新实现**按钮、徽标、空态。
- 颜色只用 `styles/tokens.css` 里的 CSS 变量，不引入新色值。
- 圆角统一走 `--radius-md`，消除 `8px`/`10px` 硬编码。
- 控件高度统一走 `--control-height` / `--control-height-sm`。

## 四、API 设计

### 4.1 `ListPage`

```vue
<ListPage
  title="模型别名"
  description="..."
  :loading="loading"
  :total="total"
  :page="page"
  :page-size="pageSize"
>
  <template #actions>   <!-- 右上主操作，透传给 BaseSection -->
  <template #filters>   <!-- FilterBar -->
  <template #toolbar>   <!-- ListToolbar -->
  <template #default>   <!-- DataTable -->
</ListPage>
```

分页由 `ListPage` 内部渲染（`total > 0` 时出现），监听 `update:page` / `update:pageSize` / `change` 向外抛。传 `:pagination="false"` 可关闭。

### 4.2 `DataTable`

```ts
interface DataColumn {
  key: string
  label: string
  width?: number | string
  minWidth?: number | string
  fixed?: boolean | 'left' | 'right'
  align?: 'left' | 'center' | 'right'
  sortable?: boolean
  ellipsis?: boolean        // 默认 true，超长省略 + tooltip
  slot?: string             // 自定义单元格插槽名，默认 cell-{key}
  headerSlot?: string
}
```

```vue
<DataTable
  :data="rows"
  :columns="columns"
  :loading="loading"
  row-key="id"
  selectable
  v-model:selection="selectedIds"
  @row-click="openDetail"
  @sort-change="onSort"
>
  <template #cell-status="{ row }">
    <BaseBadge ... />
  </template>
  <template #empty>自定义空态</template>
</DataTable>
```

`density`：`compact`（默认，对齐现有 `size="small"`）/ `default`。

### 4.4 `ListToolbar`（2026-10-21 用户反馈后重做）

**用户原话**：「要把那个批量操作的按钮改成常驻，并且按钮那一行配色也和别的一样稍微有点灰，别弄成蓝色的，并且多一个按钮，就是导出…这样列表的就算没有啥批量操作（一样可以支持导出）」

**修订后的行为**：

| 项 | 旧设计 | 新设计 |
|---|---|---|
| 显示时机 | 选中才出现 | **常驻**，永不移除 |
| 未选中时左侧 | （空） | `共 N 条 · 已启用 X 个` |
| 选中时左侧 | `已选 N 项` | `已选 N 项` + `取消选择` 链接 |
| 底色 | `--accent-blue-muted`（蓝） | `--bg-elevated`（浅灰）+ `--border-subtle` 描边 |
| 导出按钮 | 无 | **常驻**「导出」（导出全部） |
| 批量导出 | 无 | 选中后出现「批量导出（N）」 |

**导出内建在工具条里**，页面只需传 `dataset` + `selectedIds`，不用各页自己写下载逻辑。

### 4.5 导出能力（后端）

**用户确认的规格**：导出 = 全部；批量导出 = 选中哪些导哪些；格式 **xlsx**。

**端点**（`api/admin/export.py`）：

| 端点 | 行为 |
|---|---|
| `GET /admin/api/export/{dataset}` | 导出全部（受当前筛选条件约束，如 `?range=7d`） |
| `POST /admin/api/export/{dataset}` | 批量导出，body `{"ids": [...]}`；空数组 → 400 |
| `GET /admin/api/export/datasets` | 数据集清单（调试用，必须声明在 `{dataset}` 之前） |

**10 个数据集**：`pointers` / `api-keys` / `filter-rules` / `usage-by-model` / `usage-by-unit` / `usage-by-key` / `usage-logs` / `groups` / `probe-templates` / `probe-units`。

**为什么手写 xlsx 而不用 openpyxl**（关键决策）：

生产部署脚本 `deploy_v520_full.py` **只同步代码和静态产物，不在服务器上装依赖**。一旦在 `pyproject.toml` 里加 openpyxl，生产重启就会 `ImportError` → 服务起不来。

因此 `core/xlsx_writer.py` 用标准库 `zipfile` 手写 Office Open XML 最小集（6 个 part：Content_Types / .rels / workbook / workbook.rels / styles / sheet1）。已用 openpyxl 反向校验：能正常打开、表头加粗、数值是数值类型、冻结首行、自动筛选、列宽正确。

**踩到的一个坑**：`styles.xml` 里漏了 `<cellStyles>` 时，openpyxl 会警告「Workbook contains no default style」，部分 Excel 版本会提示「文件已损坏」。已补上。

**请求明细全量导出**：`usage-logs` 逐页拉取（每页 1000 条），上限 20 万条，避免一次载入撑爆内存。

**文件名**：`Content-Disposition` 同时给 ASCII 兜底名与 RFC 5987 的 `filename*=UTF-8''` 中文名（如 `API Key_20261021-2058.xlsx`），前端用独立 axios 实例读该头（共享实例的拦截器会丢掉 header）。

### 4.6 工具条按钮最终形态（2026-10-21 第三次调整）

**用户原话**：「批量导出和导出按钮交换位置，批量禁用和导出之间不需要分割线，批量导出不需要显示选中了多少条，这几个批量的按钮不管选没选中内容都要显示出来，只是没有选中内容鼠标放上去是禁用状态。」

| 项 | 最终行为 |
|---|---|
| 按钮顺序 | 批量操作（如批量删除/批量禁用）→ **批量导出** → **导出** |
| 分隔线 | **无**（批量按钮与导出之间不加竖线） |
| 批量导出文案 | 固定「批量导出」，**不显示条数**（条数在左侧「已选 N 项」已有） |
| 批量按钮显隐 | **始终显示**，`count === 0` 时 `disabled`，不靠 `v-if` 隐藏 |
| 实现方式 | `ListToolbar` 新增 `actions: RowActionItem[]` 属性，按钮组由配置驱动，未选中自动禁用 |

## 七、风险与缓解

| 风险 | 缓解 |
|---|---|
| 新组件又变成「另一套」 | 全部基于现有基础组件组合，不重复实现按钮/徽章/空态；只用 tokens 变量 |
| 迁移时破坏现有好设计 | 本轮不动现有页面；后续迁移逐页进行、逐页验收 |
| 分页全站开影响现有交互 | 本轮只在新组件里提供，现有页面行为不变 |
| 组件过度设计 | 只做用户截图里出现的 5 个要素，不做列显隐/密度切换/虚拟滚动等未提出的能力 |
