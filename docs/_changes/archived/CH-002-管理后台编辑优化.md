## 一、变更背景

v5 前端由 Streamlit 迁到 Vue 后，部分管理操作仍沿用旧式内嵌表单，体验不佳：

1. **上游源**只有新增/删除/启停，无法修改配置（改 Base URL、API Key、分组等只能删了重建）；
2. **路由规则**只有整体「可视化编辑 + 保存」和 YAML 编辑，没有直观的单条新增/修改/删除入口；
3. **模型别名**的新增/修改是页面底部的内嵌表单 + 下拉选择别名，不够直观；
4. **API Key** 只能新增/启停/删除，无法修改名称与分组。

用户期望统一为常规管理模式：**「新增」按钮弹出弹窗，列表/卡片每条带「修改」按钮弹出弹窗**。

## 二、功能范围

| 页面 | 改动 |
|------|------|
| 上游源管理 | 卡片加「修改」按钮 → 弹窗编辑（名称/Base URL/API Key 留空不改/格式/分组/探测开关） |
| 路由规则管理 | 改为规则卡片列表 + 「新增规则」按钮；每条带「修改」「删除」按钮 → 弹窗编辑（名称/匹配条件/候选模型增删改）；保留 YAML 编辑作为高级入口 |
| 模型别名管理 | 移除底部内嵌表单；改为「新增别名」按钮 → 弹窗；表格每行「修改」按钮 → 弹窗 |
| API Key 管理 | 表格每行加「修改」按钮 → 弹窗（名称/分组/启用状态） |

不在本次范围：聚合名、系统设置、延迟面板（已是常规表单/只读，无需改动）。

## 三、后端改动

**无需新增接口**，复用现有能力：

| 接口 | 说明 |
|------|------|
| `PUT /admin/api/upstreams/{id}` | CH-001 已新增，支持 name/base_url/api_key/format/group/probe_enabled/enabled |
| `PUT /admin/api/model-pointers/{name}` | 已有 |
| `PUT /admin/api/api-keys/{key}` | 已有，支持 name/groups/enabled |
| `PUT /admin/api/rules` | 已有，整体替换；弹窗单条修改后前端提交完整列表 |

说明：API Key 与上游源的 ID/Key 值为主键，弹窗中不可修改（避免破坏路由引用）。

## 四、前端改动

### 4.1 通用交互模式

所有列表/卡片页统一为：

- 顶部/底部「新增 XX」按钮 → `BaseModal` 弹出新增表单；
- 每条记录操作区「修改」按钮 → `BaseModal` 弹出编辑表单（预填当前值）；
- 「删除」保留（确认弹窗）。

### 4.2 上游源（Upstreams.vue）

- 移除底部内嵌「添加上游源」表单 → 改为「添加上游源」按钮 + 弹窗；
- 卡片操作区加「修改」按钮：弹窗编辑名称/Base URL/格式/分组/探测开关；
- API Key 输入框留空 = 不修改（后端 `exclude_none` 跳过），提示文案注明；
- ID 展示但不可编辑。

### 4.3 路由规则（Rules.vue）

- 展示区规则卡片加「修改」「删除」按钮；顶部加「新增规则」按钮；
- 规则弹窗编辑：规则名称、匹配条件（含图片/含工具调用/默认/内容关键词）、候选模型列表（增删改行：上游源/模型/权重/优先级/上下文/最大输出）；
- 保存采用整体 `PUT /admin/api/rules`（弹窗修改后提交完整列表）；
- 删除规则 = 从列表移除后整体保存；
- 「可视化编辑」tab 移除（被单条弹窗取代），保留「YAML 编辑」tab。

### 4.4 模型别名（Pointers.vue）

- 移除底部「修改别名指向」「添加新别名」两个内嵌表单；
- 加「新增别名」按钮 → 弹窗（名称/上游源/目标模型）；
- 表格每行加「修改」按钮 → 弹窗（上游源/目标模型，名称只读）。

### 4.5 API Key（ApiKeys.vue）

- 移除底部内嵌「添加新 Key」表单 → 「新增 Key」按钮 + 弹窗（名称/Key 值/分组/生成随机 Key）；
- 表格每行加「修改」按钮 → 弹窗（名称/分组/启用状态，Key 值只读展示）。

## 五、验收标准

1. 上游源/API Key：可修改名称、分组等并即时生效（热重载）；API Key 留空不覆盖上游原 Key
2. 路由规则：可单条新增/修改/删除，候选模型可编辑，保存后路由生效
3. 模型别名：新增/修改均为弹窗，操作直观
4. 所有修改类操作有成功/失败提示，删除需确认
5. 原功能（新增/删除/启停/拉取模型列表）不回退
