## 一、变更背景

两项管理端体验缺口：

1. **Base URL 黑盒**：上游源只填 base_url，用户不知道最终会拼出什么请求地址（尤其 CH-011 后不同模型可能走不同协议路径）。且源级"格式"标签在 CH-011 后语义已变为"默认协议（模型可覆盖）"，文案未更新造成困惑
2. **API Key 拿到手不会用**：创建 Key 后没有任何接入指引——请求地址是什么、模型名填什么、SDK 怎么配，用户得自己翻文档猜

## 二、详细设计

### 2.1 Base URL 拼接预览（Upstreams.vue 新增/编辑弹窗）

Base URL 输入框下方加实时预览（前端复刻后端 `_build_endpoint` 逻辑：base 已含目标路径则不重复拼接）：

```
实际请求地址：https://opencode.ai/zen/v1/chat/completions
模型列表地址：https://opencode.ai/zen/v1/models
```

- 跟随 base_url 输入实时计算
- 请求地址路径跟随"默认协议"选择联动（openai → /v1/chat/completions；anthropic → /v1/messages）
- base_url 为空时不显示

### 2.2 协议文案（Upstreams.vue）

- 新增/编辑弹窗"格式"标签 → "默认协议"
- 下方加说明：`该源模型默认使用的协议；单个模型可在模型列表中单独覆盖`

### 2.3 API Key 接入说明（ApiKeys.vue）

每行操作列加「接入说明」按钮，弹窗内容（该 Key 已预填）：

| 区块 | 内容 |
|------|------|
| 请求地址 | `http://{当前站点host}/v1/chat/completions`（从 `location.origin` 取，部署哪就是哪） |
| 鉴权方式 | `Authorization: Bearer {该Key}`（一键复制） |
| 可用模型 | 按该 Key 的分组，从 `/admin/api/upstreams` 的 models 实时算出可访问模型清单（分组 ∩ 上游 group），过多时折叠 |
| curl 示例 | 完整可跑的 chat 请求 + `GET /v1/models` 列模型 |
| Python SDK 示例 | `OpenAI(base_url=..., api_key=...)` 填好即用 |
| 流式说明 | 加 `"stream": true` 即 SSE 流式 |

- host 取 `location.origin`，不写死 IP，本地/生产都对
- 纯前端实现，零接口改动
