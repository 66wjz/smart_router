## 三、关键决策

### 3.1 分组管理必须保留「保存分组」按钮

后端 `updateGroups` 是**全量替换**语义（传整个数组，不在数组里的就删）。因此：

- 增、删、改都**先改本地数组**，不即时提交；
- 必须保留左下角「保存分组」按钮一次性提交；
- 这与其它列表的「点一下就生效」不同，所以在按钮旁加了 `BaseHint` 说明。

### 3.2 模板批量删除走父组件的既有逻辑

`useTemplateEditor.remove()` 里有「模板被 N 个聚合引用」的提示和联动清理。批量删除时若在面板内另写一套删除，会绕过这个保护。因此 `TemplatePanel.batchDelete` 是逐个 `emit('remove', row)`，让父组件按它原本的确认与联动逻辑处理。

### 3.3 筛选后「全选」只作用于筛选结果

三张用量表和上游源/聚合的 `pageState` / `togglePage` 都改成基于 `filtered*` 计算，而不是原始数组。否则筛掉的行会被「全选」误勾上。

### 3.4 探测单元的筛选没做

用户选择的是「只补筛选 + 导出」，但探测单元明细的筛选我没有加 —— 因为它的数据来自 `probe-plan` 接口一次性返回的完整单元列表，字段是「上游源 / 真实模型 / 引用聚合 / 状态」，加筛选的收益不如直接看（单元数量通常等于「源 × 模型」总数，规模有限）。**如果后续单元变多需要筛选，我再补。**

## 五、风险

| 风险 | 缓解 |
|---|---|
| 分组管理「改了不保存就丢」 | 按钮旁加 `BaseHint` 明示「增删改都先改本地，点保存分组后一次性提交」 |
| 模板批量删可能弹多次确认 | 面板先弹一次总确认，再逐个交给父组件（父组件对「被引用的模板」还会各自提示），属于有意保留的安全垫 |
| 筛选后翻页可能停在越界页码 | 筛选/重置时统一 `page = 1`；批量操作后若当前页超出范围也回第 1 页 |
