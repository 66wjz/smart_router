## 一、需求

1. **想要假数据，实际感受聚合模型与探测配置**：需要看到"异名模型被识别成一类"、"聚合组怎么配"、"探测计划长什么样"、"用量怎么按源×真实模型分布"，而不是空页面。
2. **仪表盘重新设计**：原仪表盘只有 2 张指标卡 + 上游源表格 + 快捷操作，信息密度低，作为落地首页价值不足。

### 已确认决策

| # | 决策 |
|---|---|
| 1 | 演示数据用**独立 demo 库**，不污染现有 `smart_router.db` |
| 2 | 仪表盘采用「健康条 + 5 指标 + 7 天趋势 + 上游贡献占比 + 上游卡片 + 聚合组概览 + 待关注」结构 |
| 3 | 图表用**内联 SVG 手绘**，不引入 ECharts |

## 三、仪表盘重设计

### 3.1 后端数据扩展

`GET /admin/api/dashboard` 在原有字段基础上新增：

```json
{
  "usage_today": {"requests": 56, "success_rate": 0.946, "total_tokens": 63800,
                  "active_keys": 3, "requests_delta": -0.45},
  "usage_7d": {"requests": 724, "total_tokens": 771800, "success_rate": 0.981},
  "trend": [{"date": "10-11", "requests": 82, "success_count": 81, "total_tokens": 91600}],
  "upstream_usage": [{"upstream_id": "buddy", "upstream_name": "Buddy 积分池",
                      "requests": 327, "success_count": 320, "error_count": 7,
                      "total_tokens": 376600, "share": 0.488,
                      "probe_ok": 0, "probe_total": 3, "enabled": true, "smart_retry": true}],
  "groups": [{"model": "deepseek-v4-1-flash", "member_count": 3,
              "members": [{"upstream": "buddy", "model": "deepseek-v4.1-flash"}],
              "configured": true, "probe_enabled": true, "probe_interval": 60,
              "probe_schedule": "工作日 08:00-23:00", "probe_schedule_mode": "window",
              "sort_mode": "latency", "requests_7d": 297, "tokens_7d": 268700}],
  "attention": [{"kind": "probe_down", "target": "gemini-2.5-pro@buddy",
                 "detail": "探测不可用：..."}],
  "probe_summary": {"enabled": true, "unit_count": 7, "ok": 0, "down": 4, "unknown": 3,
                    "global_interval": 300, "global_schedule": "全天候", "scheduled_off": 3}
}
```

数据来源：

| 块 | 来源 |
|---|---|
| usage_today / usage_7d | `UsageRepository.summary()` |
| trend | `UsageRepository.daily_trend(7)`（按本地自然日，缺失日期补 0） |
| upstream_usage | `UsageRepository.by_upstream("7d")` + 探测可用率 |
| groups | `config.collect_group_members()` + `group_probe_settings()` + `by_request_model("7d")` |
| attention | `health.get_status()` + `probe.data` + 上游 Key 数 / 启用状态 |
| probe_summary | `config.collect_probe_plan()` + `probe.data` + 全局配置 |

### 3.2 前端结构

```
① 健康条：探测开关/间隔 │ 单元数（可用/不可用/未知）│ 全局探测时段 + 时段外数量 │ 7天成功率 │ 待关注数
② 5 张指标卡：今日请求（环比）│ 今日 Tokens │ 今日成功率 │ 活跃 Key │ 聚合组
③ 两栏：近 7 天双指标趋势（SVG 折线+面积）│ 上游源贡献占比（横向条 + 失败数）
④ 上游源卡片（4 列）：状态点 + 分组 + 模型/Key/7天请求/Tokens + 探测可用率 + 智能重试
⑤ 聚合组概览（2 列）：手动配置/自动发现 + 探测徽标 + 排序模式 + 成员链路 + 近 7 天用量
⑥ 需要关注：冷却中 / 探测不可用 / 无可用 Key / 数据陈旧 / 已禁用
```

交互：指标卡与聚合组卡片可点击跳转；右上「刷新」。

### 3.3 图表实现

内联 SVG，零依赖：

- 请求数：`polyline` + `polygon` 面积填充（渐变）
- Tokens：虚线 `polyline`，与请求数各自独立归一化
- 悬浮：`<rect>` + 原生 `<title>` tooltip
- 空数据：显示「近 7 天暂无请求」

## 四、实施中修复的三个问题

| # | 问题 | 根因 | 修复 |
|---|---|---|---|
| 1 | 探测计划出现 `buddy:deepseek-v4-1-flash`（聚合名当成模型名） | `collect_probe_plan` 对规则候选/别名目标直接取 `(upstream, model)`，未展开聚合名 | 规则与别名引用聚合名时改为展开成各源真实模型名；演示库探测单元从 11 → 7 |
| 2 | 仪表盘「今日请求」= 14 天总量 | `_range_clause("today")` 用 `created_at`（批量落库时间），历史数据一次性导入时全算进"今日" | 改用请求时间 `ts`（本地自然日 0 点起） |
| 3 | 趋势图完全不显示 | `style.css` 全局规则 `svg:not([width]) { width: 1em !important }` 把内联 SVG 压成 14px | 趋势图显式声明 `width`/`height` 属性，并在全局规则中排除 `.trend-svg` |

附带优化：环比改为「今日 0 点到现在」对比「昨日同期」，避免半天 vs 全天的误导。
