## 二、根因定位（先定位再改）

### 2.1 问题 2：三个保存按钮不对齐

`Settings.vue` 三段表单的 `label-width` 不一致：

| 表单 | `label-width` | 保存按钮实测 x 坐标 |
|------|--------------|-------------------|
| 请求重试 | `140px`（第 13 行） | 364 |
| 智能重试 | `160px`（第 41 行） | 384 |
| 故障转移 | `140px`（第 67 行） | 364 |

保存按钮放在无 label 的 `el-form-item` 内，左边界 = label 宽度，所以 140 与 160 相差 20px，视觉上「智能重试」那个明显偏右。

**修法**：三段表单 `label-width` 统一为 `160px`，三个按钮左边界归到同一 x 坐标。

### 2.2 问题 3：规则弹窗选不到模型

`Rules.vue:219` 用的是 `fetchUpstreamModels(id)`：

```
GET /admin/api/upstreams/{id}/models
  → backend/app/api/admin/upstreams.py:58-83
  → 实时请求上游远端 {base_url}/v1/models
  → 失败/超时/无 base_url 时一律返回 {"models": []}
```

该接口设计用途是「上游源管理页的拉取远端正本模型」。演示环境上游是假地址，必然返回空数组，于是模板走 `v-else` 分支退化为手动输入框（`Rules.vue:84-93`）。

对比：同项目「聚合模型」页用的是读库接口，实测正常：

| 接口 | 数据来源 | buddy 源实测 |
|------|---------|-------------|
| `GET /admin/api/upstreams/buddy/models` | 实时拉远端 `/v1/models` | `{"models": []}` |
| `GET /admin/api/model-groups/source-models?upstream=buddy` | 读库中 `up_upstream.models` | 3 个模型 |

**修法**：`Rules.vue` / `Pointers.vue` 改用 `listSourceModels(upstream)`（`api/model_groups.ts:44`），与聚合成员选择保持同一数据源。

**行为变化声明**：候选模型来源从「上游实时模型列表」变为「该上游已配置的模型列表」。
- 好处：不再受上游是否可达影响，演示环境也能正常下拉。
- 代价：远端有但没在后台配过的模型不会出现在下拉里（可先在「上游源管理」页拉取并保存）。
- 兜底：若该源尚未配置任何模型，仍保留手动输入框（现有 `v-else` 分支不动）。

### 2.3 问题 5：聚合列表为什么现在不能拖

1. `agg_unified` 表**没有任何显示排序字段**（建表见 `sql/increment/07_...sql:25-42`），只有 `sort_mode`——它控制探测排序策略，不是展示顺序。
2. 列表顺序写死为 `ORDER BY kind, name`（`aggregation_repo.py:94`），并且 Python 层又排了一次 `sorted(key=(kind != "static", name))`（`config_service.py:327`）。
3. 自动发现但未落库的聚合追加在最后（`config_service.py:376`）。
4. 项目已有 `sortablejs` 依赖（`package.json:17`），且已有两种成熟用法可参照：`useUpstreamModels.ts:196-246`（落库型）、`MemberEditor.vue:105-124`（纯前端型）。

## 三、目标与方案

### 3.1 分组管理「+ 添加分组」规范化

- 从表格下方移入 `BaseSection` 的 `#actions` 插槽（右上角），与「新建聚合」同位置。
- 变体由 `ghost` 改为 `primary`，与「+ 新建聚合」配色一致。
- 底部只保留「保存分组」（左下角），符合 CH-027 规范二（区块级保存按钮左下角）。

结果：右上角「+ 添加分组」、左下角「保存分组」，与聚合模型页形态一致。

### 3.2 全局容错保存按钮对齐

- `Settings.vue` 三段 `el-form` 的 `label-width` 统一为 `160px`。

### 3.3 规则/别名候选模型改为可选

- `Rules.vue`：`fetchUpstreamModels` → `listSourceModels`，响应 `{models: [{name, enabled}]}` 映射为名字数组。
- `Pointers.vue`：同样替换（新增别名、修改别名两处弹窗共用同一份 `modelsByUpstream`）。
- 不改 `useUpstreamModels.ts`：上游源管理页的「拉取模型」是真实需要的远端拉取，保持原样。

### 3.4 YAML 编辑卡片化

**现状**（`Rules.vue:118-130`）：一个 `el-collapse` 折叠面板，展开后是一个 14 行 textarea + 两个按钮。

**目标**：改成与「默认对话」规则卡片同构的独立卡片：

```
┌─ YAML 编辑（高级） ────────────────────── [ 修改 ] ┐
│ 说明：直接编辑 JSON 格式的路由规则…                │
│ ┌──────────────────────────────────────────────┐ │
│ │ {                                            │ │
│ │   "name": "默认对话",                          │ │  ← 只读，可滚动
│ │   ...                                         │ │
│ │ }                                             │ │
│ └──────────────────────────────────────────────┘ │
└──────────────────────────────────────────────────┘
```

- 卡片用 `BaseSection variant="card"`，标题「YAML 编辑（高级）」，「修改」按钮挂 `#actions`（右上角）。
- 卡内只读展示当前规则源码，等宽字体，`max-height` 约 320px，超出滚动。
- 点「修改」弹出 `BaseModal size="large" height="70vh"`，内含可编辑 textarea。
- 弹窗底部用 `BaseModalFooter`：左侧「重新加载」（恢复为当前已保存内容）+ 取消 + 保存。
- 保存逻辑沿用现有 `handleSaveYaml`（JSON 解析 + 整体保存 + 热重载）。

> 说明：内容格式仍为 JSON（与后端 `PUT /admin/api/rules` 的请求体一致），未引入 YAML 解析库，避免新增依赖。标题沿用「YAML 编辑（高级）」以保持用户认知一致，卡片说明里写明实际为 JSON 格式。

### 3.5 聚合列表拖拽排序

**为什么不用新增表字段**：`agg_unified` 只存「已配置」聚合，自动发现的聚合没有行（`configured=false`）。若用 `sort_order` 列，未落库的聚合无法参与排序，体验断裂。

**方案：顺序存 `sys_setting` 的自定义键**

与既有 `groups` 键（`config.py:224-237`）同一模式，零表结构变更。

**后端改动**

| 文件 | 改动 |
|------|------|
| `backend/app/core/config.py` | 新增 `aggregation_order` 属性（读 `sys_setting.aggregation_order`，默认 `[]`）+ `set_aggregation_order(names)`（写库并刷新内存 `_settings`），放在 `get_groups/set_groups` 旁边 |
| `backend/app/services/config_service.py` | `list_aggregations()` 末尾按 `aggregation_order` 重排：命中数组的按数组顺序在前，未命中的保持原 `kind+name` 顺序追加；数组里已不存在的名字自动忽略 |
| `backend/app/api/admin/aggregations.py` | 新增 `PUT /admin/api/aggregations/order`，body `{names: [str]}`，写库后返回 `{ok, count}` |

排序语义（明确声明）：
- `aggregation_order` 为空 → 完全沿用现有 `kind+name` 顺序（不改变任何存量环境的表现）。
- 拖拽一次后 → 全量写入当前可见顺序（含自动发现项）。
- 新增聚合 → 不在数组里，排在末尾，不影响已排好的顺序。
- 删除聚合 → 名字仍在数组里但不在列表中，读取时忽略，无需清理。

**前端改动**

| 文件 | 改动 |
|------|------|
| `frontend/src/api/aggregations.ts` | 新增 `reorderAggregations(names)` → `PUT /admin/api/aggregations/order` |
| `frontend/src/views/Aggregated.vue` | 卡片列表容器加 `ref` + `data-sortable-aggregations`；用 `sortablejs` 初始化（`handle: '.drag-handle'`、`animation: 150`、`ghostClass: 'drag-ghost'`）；`onEnd` 先本地重排 → 调接口 → `reloadConfig()`；失败则 `loadAll()` 复原 |
| `frontend/src/components/aggregation/AggregationCard.vue` | 标题行最左加拖拽手柄 `⠿`（`.drag-handle`），`cursor: grab`，hover 时高亮；不改变任何现有操作按钮的位置 |

> 手柄放最左侧而不是包裹整张卡片：卡片内有 `el-switch`、按钮等交互元素，整卡可拖会与点击/切换冲突。这与上游源模型拖拽（`ModelList.vue` 用 `.drag-handle`）保持一致。

## 七、风险与回退

| 风险 | 影响 | 缓解 |
|------|------|------|
| 候选模型改为读库后，远端有但未配置的模型选不到 | 需先到上游源页拉取并保存 | 卡片说明写明来源；无模型时保留手动输入框 |

| `aggregation_order` 写入了已删除的名字 | 顺序错乱 | 读取时忽略不存在的名字 |

回退方式：本次为独立改动，按文件粒度 `git checkout`；`sys_setting.aggregation_order` 键可保留（为空时行为与改前一致），无需删库。
