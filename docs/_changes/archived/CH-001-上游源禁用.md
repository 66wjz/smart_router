## 一、变更背景

用户在使用管理后台时提出：上游源管理需要支持「禁用」操作。当前上游源只有增删查，无法在不删除配置的前提下临时停用某个模型提供商。

## 二、功能语义

**完全禁用**：禁用的上游源，其下所有模型**不参与**智能路由、延迟探测、别名转发、直接透传。请求命中禁用上游返回 503。配置全部保留，可随时恢复启用。

**默认状态**：存量上游源迁移后全部默认启用（enabled=1）。

## 三、影响面

| 层 | 改动 | 说明 |
|----|------|------|
| 数据库 | up_upstream 增加 enabled 字段 | 增量 SQL，不改原建表文件 |
| 配置层 | AppConfig 增加 enabled 读取与过滤 | get_upstream 返回 enabled；路由/探测跳过禁用上游 |
| 后端 API | 新增 PUT /admin/api/upstreams/{upstream_id} | 支持修改 enabled 等字段 |
| 路由引擎 | 候选模型过滤禁用上游 | 别名/透传/聚合路由均拦截 |
| 延迟探测 | 探测循环跳过禁用上游的模型 | 避免无效请求 |
| 前端 | 上游源卡片加「启用/禁用」开关 | 禁用状态灰色标识 |

## 四、详细设计

### 4.1 数据库

增量 SQL `sql/increment/01_增量_20260809_上游源禁用.sql`：

```sql
ALTER TABLE up_upstream ADD COLUMN enabled INTEGER NOT NULL DEFAULT 1;
```

### 4.2 配置层（AppConfig）

- `get_upstream(upstream_id)`：返回完整配置（含 enabled 字段），调用方自行判断
- 新增辅助 `is_upstream_enabled(upstream_id) -> bool`：未配置时默认 True
- 路由候选过滤：`get_ordered_candidates` 中，若候选 upstream 被禁用，则该候选排除
- 别名/直接透传：`_resolve_candidates` 中检查目标 upstream 是否启用，禁用则抛 503

### 4.3 后端 API

新增端点：

```
PUT /admin/api/upstreams/{upstream_id}
入参: { enabled?: bool, name?, base_url?, api_key?, format?, group?, probe_enabled? }
出参: { "ok": true }
错误: 404 上游源不存在
```

### 4.4 延迟探测

`LatencyProbe._init_models()`：过滤掉上游被禁用的模型。

### 4.5 前端

上游源卡片增加状态标识（启用/禁用）+ 切换开关按钮。禁用卡片置灰。

## 五、验收标准

1. 管理后台可对上游源执行启用/禁用，状态即时反映
2. 禁用上游后：智能路由不选其模型、别名指向禁用上游返回 503、直接透传返回 503、探测跳过
3. 恢复启用后：一切行为恢复正常
4. 存量上游源迁移后默认启用
