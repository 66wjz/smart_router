## 三、根因定位

### 3.1 问题 1：全新环境启动崩溃（已实测复现）

`sql/01_建表.sql` 的 `up_upstream` 只有 10 个字段，缺 `enabled` / `models` / `smart_retry` / `groups`；全文没有 `up_upstream_key` 表。这 5 项分别由增量 01~05 补齐。

而 `backend/seed.py:42-43` 只执行 `01_建表.sql` + `02_init_data.sql`，**不执行任何增量**；`main.py` 的 `startup()` 只自动补 06/07/08 与 `log_usage.upstream_model`。

更关键的是：`AppConfig.load()` 里 `_load_upstream_keys()` 在 `try/except sqlite3.OperationalError` 之外（`backend/app/core/config.py:103`），查不存在的 `up_upstream_key` 会抛异常且无人捕获。

实测结果（临时空库，只跑 seed 的两个 SQL）：

```
表: ['agg_aggregated_name', 'agg_model_group', 'api_api_key', 'log_usage',
     'pt_pointer', 'rule_candidate', 'rule_rule', 'sqlite_sequence',
     'sys_setting', 'up_upstream']
up_upstream 列: ['id','upstream_id','name','base_url','api_key','format',
                'group_name','probe_enabled','created_at','updated_at']
有 up_upstream_key: False
  up_upstream.enabled: False
  up_upstream.models: False
  up_upstream.smart_retry: False
  up_upstream.groups: False
```

再调 `AppConfig.load()`：

```
sqlite3.OperationalError: no such table: up_upstream_key
  at app/core/config.py:136 → _load_upstream_keys
```

**结论**：任何全新环境 / 灾备重建都起不来。

### 3.2 问题 2 / 3：seed.py 的两个缺陷

- `drop_all()` 只删 7 张表（`seed.py:17-20`），漏 `up_upstream_key` / `log_usage` / `agg_model_group` / `agg_probe_config` / `agg_probe_template` / `agg_unified`。重跑 seed 后 `agg_unified` 因 07 是 `INSERT OR IGNORE` 不会被覆盖，旧聚合/绑定残留。
- DB 路径写死 `backend/smart_router.db`（`seed.py:11`），而运行时支持 `SMART_ROUTER_DB`（`database.py:14`），设了环境变量时会把种子写进错误的库。

## 四、方案

### 4.1 修问题 1：把增量 01~05 纳入 seed 执行序列

**不修改 `01_建表.sql`**（避免改动历史基线、影响已部署环境），而是在 `seed.py` 里按既有顺序追加执行增量脚本：

```python
run_sql_file(conn, "01_建表.sql")
run_sql_file(conn, "02_init_data.sql")
run_sql_file(conn, "increment/01_增量_20260809_上游源禁用.sql")
run_sql_file(conn, "increment/02_增量_20260809_上游Key池.sql")
run_sql_file(conn, "increment/03_增量_20260809_上游模型列表.sql")
run_sql_file(conn, "increment/04_增量_20260810_智能重试开关.sql")
run_sql_file(conn, "increment/05_增量_20260811_上游多分组.sql")
run_sql_file(conn, "06_用量统计与自动聚合.sql")
run_sql_file(conn, "increment/06_增量_20261017_聚合探测配置.sql")
run_sql_file(conn, "increment/07_增量_20261017_聚合统一与探测模板.sql")
run_sql_file(conn, "increment/08_增量_20261017_聚合规则绑定.sql")
```

理由：增量脚本本身是幂等/一次性 DDL，按 `test/seed_demo_ch022.py:441-453` 已验证的顺序执行即可。这样 `seed.py` 一次跑完就能得到完整结构，无需人工补跑。

### 4.2 修问题 2：`drop_all` 补齐

补上 6 张表：`up_upstream_key`、`log_usage`、`agg_model_group`、`agg_probe_config`、`agg_probe_template`、`agg_unified`。

### 4.3 修问题 3：`seed.py` 支持 `SMART_ROUTER_DB`

```python
DB_PATH = os.environ.get("SMART_ROUTER_DB") or os.path.join(os.path.dirname(os.path.abspath(__file__)), "smart_router.db")
```

与 `database.py:14` 口径一致。

### 4.5 修问题 5 / 6 / 7：文档补全

- `数据库设计.md` 3.9：补 `log_routing`、`usage_retention_days`。
- `API契约.md`：把「拉取模型列表｜前端直连上游」改为「后端代理 `GET /admin/api/upstreams/{id}/models`」。

### 4.6 修问题 8：`start.bat` 指向 v5 启动方式

当前 `start.bat:15` 是 `python router.py`（v4 遗留，无鉴权、无 SQLite）。改为指向 `backend/run.py`，避免运维误启旧服务。

## 七、验收标准

5. **版本号一致**：`main.py` / `run.py` / `README.md` / `STATE.md` / `pyproject.toml` / `package.json` 均为 5.2.0。
6. **不影响现有库**：在 `demo.db` 上跑既有三套回归脚本仍全通过。
7. **构建通过**：`npm run build` 通过（package.json 版本号变更不影响构建）。
