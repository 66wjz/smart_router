# CH-043 卡片壳与成员流组件统一 + 批量操作选中保持

> 类型：B 线-中（抽二级组件 + 交互修正，纯前端）
> 状态：已实现 + 浏览器逐项验证通过（2026-10-22）
> 日期：2026-10-22
> 来源：用户反馈三点 —— ①批量操作后选中丢失 ②仪表盘贡献占比过多撑变形 ③聚合模型/疑似同一模型/上游源应视为同一种列表
> FB 编号：FB-035

---

## 一、要解决的三个问题

### 问题 1：批量操作后选中丢失

| 现象 | 根因 |
|---|---|
| 点「批量启用/禁用」后勾选全没了，要重新选 | `ApiKeys.batchToggle` 末尾主动调 `clearSelection()` |
| 翻页后勾选丢失 | `DataTable` 的 selection 列未开 `reserve-selection` |
| 批量删除后可能残留幽灵选中 | 删除后 `selected` 仍指向已不存在的行 |

### 问题 2：仪表盘撑变形

`.share-list` 无高度约束，14 个上游 → 约 700px 高；`.two-col` 是 grid，默认 `align-items: stretch`，右侧被撑多高左侧图表卡就被拉多高 → 左侧大片空白。

### 问题 3：同一种列表写了多套

三处「主从卡片」结构同源，但各写一套：

| 重复项 | 份数 | 具体类名 |
|---|---|---|
| 卡片外壳 | 6 | `.upstream-card` / `.group-card` / `.suggest-card` / `.up-card` / `.grp-card` / `.dp-card` |
| 只读 chips 流 | 4 | `.source-flow` / `.suggest-members` / `.grp-flow` / `.dp-model-chips` |
| chip 样式 | 4 套 | `.source-chip` / `.member-chip` / `.grp-chip` / `.dp-chip` |

## 二、用户拍板的方案

| 决策点 | 用户选择 |
|---|---|
| 统一程度 | **路线 A**：抽 `ChipFlow` + `EntityCard`，不做 DataTable 展开行（保留上游源卡片外观） |
| 成员超出时的形态 | **不用「展开/收起」按钮，改成分页**：「下面显示前多少条，可以切换页」——与列表组件的分页形态保持一致 |

### 2.1 分页式成员流的细节约定

- 默认每页 10 个；`items.length <= pageSize` 时**不渲染分页条**（避免 2~6 个成员时出现冗余控件）
- 分页条视觉与 `TablePagination` 对齐：`共 N 个` + 上一页/页码/下一页，右对齐，字号 13px
- 每个 chip 带**序号**，分页后仍知道它在链路中的位置
- 最后一个 chip 标「兜底」、第一个标「首选」（仅聚合链路启用）

## 三、组件设计

### 3.1 `ChipFlow`（新增，`components/base/`）

只读成员集合流。放 `base/` 而非 `list/`，因为它是最小展示单元，不是列表页。

```ts
props: {
  items: any[]                    // 成员数组
  pageSize?: number               // 默认 10
  chipKey?: (item, i) => string   // 稳定 key，默认 upstream+model
  renderUpstream?: (item) => string
  renderModel?: (item) => string
  showIndex?: boolean             // 显示 1/2/3 序号，默认 true
  showFirstLastTag?: boolean      // 首个标「首选」、末个标「兜底」，默认 false
  arrow?: boolean                 // chip 之间是否显示 →
}
```

内部状态：`page`。`items` 变化时重置到第 1 页。

底部（`items.length > pageSize` 时）：

```
共 14 个                              ‹ 1 2 ›
```

### 3.2 `EntityCard`（新增，`components/base/`）

主从卡片外壳。

```ts
props: {
  title?: string
  disabled?: boolean              // 整卡降透明度
}
slots: {
  title      // 标题区：名称 + 徽标组
  actions    // 右上操作区
  meta       // 元信息行（ID / baseURL 等，可选）
  default    // 正文（成员流 / 模型列表）
  footer     // 底部（探测状态等，可选）
}
```

统一：`border-radius: var(--radius-md)`、`padding: 14px`、`margin-bottom: 12px`、`border: 1px solid var(--border-subtle)`。

## 五、验证方式

1. `npm run build` 通过
2. API Key 页：勾选 3 条 → 批量禁用 → **3 条仍被勾选**；勾选 2 条 → 批量删除 → 选中数归零且无幽灵选中
3. API Key 页：勾选后翻页再翻回，选中保持
4. 仪表盘：上游源 10+ 时贡献占比内部滚动，左侧图表高度不被拉长
5. 聚合模型：成员 6 个以内不出现分页条；超过 10 个时出现分页且页码可用；首个显示「首选」、末页最后显示「兜底」
6. 疑似同一模型：成员超 10 个时出现分页
7. 视觉与现有页面同一套令牌（圆角 / 间距 / 字号）

## 六、风险

| 风险 | 缓解 |
|---|---|
| 抽组件后上游源卡片视觉被改变 | `EntityCard` 的 padding/radius 按现有上游卡片的 16px/10px 对齐；只替换外壳，内部模型列表原样保留 |
| 分页在少量成员时反而多余 | 只有 `items.length > pageSize` 才渲染分页条 |
| 批量删除求交集逻辑出错导致漏选 | 求交集基于 `row-key`，且删除后重新拉取最新列表再计算 |
