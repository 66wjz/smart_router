## 一、变更背景

用户客户端直连 opencode 模型（mimo-v2.5 / deepseek-v4-flash）报 503"所有模型均不可用"。根因：`config.find_model_upstream` **只在路由规则候选中查找模型**，找不到落默认源（newapi）→ 默认源没有该模型 → 失败。

设计缺口：上游源的"已配置模型列表"（CH-005 建立、/v1/models 已用它做展示）没有参与透传查找，导致"源上配好了、模型列表能看到、却调不通"的割裂。

## 二、详细设计

`find_model_upstream` 查找顺序调整为：

```
1. 路由规则候选（现状不变，规则优先）
2. 上游源已配置模型（新增：遍历启用上游的 models 条目 name 精确匹配，命中返回该上游）
3. 默认源兜底（现状不变）
```

- 只匹配**启用**的上游源（禁用源不参与，与 `_check_group` 的禁用拦截一致）
- 命中后照常走 `_check_group` 分组权限检查（已有逻辑，free Key 命中 premium 源模型会 403，无安全缺口）
- 多源配置了同名模型时，按上游配置顺序取第一个（与规则查找的"先见先得"语义一致）
