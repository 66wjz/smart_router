# CH-031 仓库迁移 GitHub + Git 历史隐私清洗

> 类型：B 线-小（仓库卫生 + 安全合规）
> 状态：已实现（本地完成清洗，**未 push、未部署**）
> 日期：2026-10-18

---

## 一、背景

用户准备把代码推送到远端仓库，推送前提出三点疑虑：

1. 本次待推的更改是否有隐私泄露；
2. 远端仓库已有的历史提交是否有泄露风险（用户只在本地提交，担心历史提交带出敏感信息）；
3. 继续用 Gitee 还是迁到 GitHub。

审查结果（推送前扫描）：

| 项 | 结论 |
|---|------|
| 本次待推 13 个提交（CH-026~030） | 96 个文件，**干净**，无凭据 |
| git 历史 | **存在泄露**：`test/verify_prod_ch016.py` 在 `e2df186`（CH-016，2026-08-11）中含硬编码管理员密码与客户端 Key；`521ac20`（CH-018）已改为环境变量，但历史仍可翻阅 |
| `.git/config` 远端 URL | 内嵌明文 Gitee 账号密码 |
| 历史中的内网/公网 IP | `8.137.195.192` / `10.10.0.2` / `124.222.235.3`——用户明确不处理（局域网部署，外部不可达） |

用户决策：

1. **迁到 GitHub**，原 Gitee 仓库**转私有**（用户在网页操作）；
2. 推送前**先把历史清干净**再推；
3. **不轮换**已泄露的凭据（局域网部署，外部访问不到）。

## 三、方案

### 3.1 双重备份（清洗前，已完成）

| 备份 | 路径 | 大小 |
|------|------|------|
| 工作区文件副本 | `E:\80-project_dev\04_smart-router-backup-20261018` | 1.8 MB（排除 node_modules/.venv/dist/logs/__pycache__/*.db） |

> bundle 保留**清洗前**的完整历史（含泄露内容），仅作本地灾备，**绝不外传、绝不上传**。

### 3.2 历史清洗

工具：`git-filter-repo` v2.47.0（`uv tool install git-filter-repo`）。

替换规则（临时文件 `.git/replace-rules.txt`，**用后立即删除，绝不提交**）：

```
<真实管理员密码>  ==> CHANGE-ME-ADMIN-PASSWORD
<真实客户端 Key>   ==> sk-CHANGE-ME-CLIENT-KEY
```

执行：

```
git filter-repo --replace-text .git/replace-rules.txt --force
```

- 解析 27 个提交，0.41s 完成重写
- `filter-repo` 按设计移除 `origin` 远端（与本需求一致：换 GitHub）
- 旧对象已 repack 清理

### 3.4 远端配置

- GitHub 远端**待用户提供仓库地址后**再配置，本次不配置、不推送

| 风险 | 影响 | 缓解 |
