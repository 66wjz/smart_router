# 变更：三协议入站行为统一修复（图片透传 + 错误格式 + 推理模型 reasoning）

> 编号：CH-018
> 日期：2026-08-12
> 分类：A 线 bug（FB-020，分两期实施）
> 状态：已修复+已部署+已归档（生产 8.137.195.192:10002）
> 关联：CH-009（anthropic 入站）、CH-010（responses 入站）

---

## 一、变更背景

用户用 Chatbox / Claude Code / Codex 对接三协议入站时发现行为不一致：

1. **图片丢失**：anthropic 入站发图 AI 回复但看不到图；responses 入站发图空回复。根因：CH-009/CH-010 的入站转换器漏了图片块映射（anthropic `image` 块、responses `input_image` 块被静默丢弃）。
2. **错误格式不兼容**：模型不支持图片时（如 deepseek-v4-flash），`/v1/messages` 与 `/v1/responses` 抛 `HTTPException` 走 FastAPI 默认 `{"detail":...}`，Anthropic/Responses SDK 解析失败 → 客户端表现为"超时无反馈"。
3. **推理模型内容丢失**：mimo-v2.5 等推理模型的 `reasoning` 内容在 messages/responses 入站转换中被丢弃，max_tokens 偏小时正文为空 → "没结果返回"。

目标：三协议（OpenAI 兼容 / Anthropic messages / Responses）行为统一，各客户端（Chatbox / Claude Code / Codex）可直接对接。

## 二、详细设计

### 2.1 入站图片块映射（一期）

| 入站协议 | 图片块 | 转换目标 |
|---------|--------|---------|
| anthropic | `{"type":"image","source":{"type":"base64","media_type","data"}}` | openai `{"type":"image_url","image_url":{"url":"data:{media};base64,{data}"}}` |
| anthropic | `{"type":"image","source":{"type":"url","url"}}` | openai `{"type":"image_url","image_url":{"url"}}` |
| responses | `{"type":"input_image","image_url"}` | openai `{"type":"image_url","image_url":{"url"}}` |

- 纯文本消息保持 `content` 为字符串（不回归）；含图片时转为块列表。
- 修复后三入口图片真实透传：支持图片的模型正常识别，不支持的模型由上游拒绝报错（与 OpenAI 兼容行为一致）。

### 2.2 三入站错误格式统一（二期）

| 入站 | 错误格式 |
|------|---------|
| openai | `{"error":{"message","type":"api_error","code"}}` |
| anthropic | `{"type":"error","error":{"type":"api_error","message"}}`（400/401/403/429/503 映射各协议 etype） |
| responses | `{"error":{"message","type","code"}}` |

- `svc.chat_completions()` 抛出的 `HTTPException` 在入站层捕获并按协议格式包装。

### 2.3 推理模型 reasoning 映射（二期）

| 层 | openai 字段 | 目标 |
|----|------------|------|
| anthropic 非流式 | `message.reasoning` / `reasoning_details[]` | content 内 `{"type":"thinking","thinking"}` 块 |
| anthropic 流式 | `delta.reasoning_content` / `delta.reasoning` | `content_block_start(type=thinking)` + `content_block_delta(type=thinking_delta)` |
| responses 非流式 | `message.reasoning` / `reasoning_details[]` | output 内 `{"type":"reasoning","summary":[{"type":"summary_text"}]}` |
| responses 流式 | `delta.reasoning_content` / `delta.reasoning` | `response.reasoning_summary_text.delta` + reasoning item 生命周期 |

- **兼容两种上游字段**：deepseek 官方流式用 `reasoning_content`；opencode go 上游实测用 `reasoning`（抓原始 SSE 确认）。
- content 为空但 reasoning 存在时仍返回 thinking/reasoning，避免"空结果"。

## 四、验证

### 一期（本地 5 用例）

anthropic 混合块（text+base64+url）/ 纯文本 / 仅图片；responses 混合 / 纯文本 / 仅图片；闭环 image 无损。

### 二期（本地 16 用例 + 生产 11 项）

- 三协议错误格式：deepseek-v4-flash 发图 → 503 + 各协议标准错误（openai/anthropic/responses）
- mimo-v2.5 发图（支持图片）：messages 3 次非空 / responses 3 次含 reasoning+message / 流式含 thinking_delta
- 兼容 `delta.reasoning`（opencode go 真实字段）+ `delta.reasoning_content`（deepseek 官方）
- 工具调用：messages 流式 tool_use 事件完整
