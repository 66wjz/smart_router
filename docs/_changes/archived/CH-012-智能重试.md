## 一、变更背景

opencode 类不稳定上游在工作日高峰频繁返回 500 / TLS 握手中断，但几秒后可恢复（抖动型故障）。现有容错体系（候选转移 / Key 池轮换 / 模型冷却 / 延迟探测）是为**聚合模型路由**设计的——前提是同逻辑模型后挂多个上游可切。当客户端直连某上游的单个模型（候选只有 1 个）时，上游一次 500 = 客户端立刻掉线：

- 适配器对非 401/403/429 的错误（含 5xx）直接 `record_fail` + 返回 None，**无同渠道退避重试**
- 单 Key 时连接超时/429 也没有额外重试预算

## 二、方案取舍（对参考文档的加减法）

参考文档提出的三级容错，对照现状：

| 参考文档 | 现状/决策 |
|---------|----------|
| 流式首字节分界线 | ✅ 已实现（try_stream 拿到首行才提交 StreamingResponse），不重做 |
| 跨渠道故障转移 + model_map | ✅ 已实现（候选列表 + 候选自带实际模型名），不重做 |
| Key 级失败轮换 | ✅ 已实现（Key 池），作为智能重试的组成 |
| **同渠道退避重试（5xx/连接错误）** | ❌ 缺失，**本变更核心** |
| 429 退避 | ❌ 缺失（429 只换 Key，单 Key 时直接失败），本变更补 |
| 失败率窗口 + 半开熔断状态机 | ❎ 不做（现有模型级冷却 + 探测已覆盖"渠道死了别去撞"，复杂度收益比低） |
| 30s 主动探测 | ❎ 不做（现有 360s 探测够用，避免白烧免费额度） |
| X-Served-By 响应头 | ❌ 缺失，本变更顺手补（调试可确认走了哪个渠道/重试几次） |

## 三、详细设计

### 3.1 开关与配置

- `up_upstream` 表新增列 `smart_retry INTEGER NOT NULL DEFAULT 0`（增量 SQL `04_增量_20260810_智能重试开关.sql`）
- **默认关闭**：关闭 = 现有行为逐字节不变，不影响在跑的所有源
- 全局参数存 `sys_setting.smart_retry`（JSON，Settings 页可改）：

```json
{ "extra_attempts": 2, "backoff_ms": [500, 1500], "jitter": 0.2 }
```

| 参数 | 默认 | 说明 |
|------|------|------|
| extra_attempts | 2 | Key 轮换之外的额外重试次数 |
| backoff_ms | [500, 1500] | 同 Key 第 n 次退避毫秒数 |
| jitter | 0.2 | ±20% 随机抖动，防多客户端同步重试 |

### 3.2 重试语义（开关打开时）

```
可重试错误集合 = 5xx(500/502/503/504) + 429 + 连接超时 + 连接重置 + TLS 中断 + 读超时/首包超时 + 空响应
不可重试 = 其他 4xx（400/401/403/404/422 等，请求本身的问题）
注：401/403/429/超时 换 Key 是现有行为，与开关无关；开关把 5xx/连接错误 纳入同一循环

重试预算 = Key 数量 + extra_attempts
每次失败后：
  - Key 池能换到不同的 Key → 立即用新 Key 重试（无退避）
  - 只能回到同一个 Key → 按 backoff_ms[n] × (1±jitter) 退避后重试
预算耗尽 → 返回 None → 走现有候选转移（如有 fallback 源）→ 最终 503
```

流式请求：首字节前的失败按上述重试；**开始吐字后中断不重试**（现有分界天然保证），只记录并关流。

### 3.4 响应头（调试可观测）

成功响应统一加：
- `X-Served-By: {upstream_id}/{model}`
- `X-Retry-Count: {n}`（本次请求在源内重试了几次，0 = 一次成功）

### 3.5 日志

每次重试打 warning：`[smart-retry] {upstream}/{model} 第n次失败: HTTP 500 → 换Key重试 / 退避500ms后同Key重试`。

## 四、影响面

- 开关关闭的源：行为完全不变（回归验证重点）
- 探测（probe）：不受影响（probe 有自己的轻量请求逻辑，不走转发重试）
- 聚合路由：候选转移逻辑不变，智能重试是"每个候选内部"的增强

## 五、验证

- 本地 mock 上游（可编程返回 500×N 后 200）：
  - 开关关：一次 500 → 立即失败（回归不变）
  - 开关开 + 单 Key：500 → 退避重试 → 第 2 次成功，响应头 X-Retry-Count=1
  - 开关开 + 双 Key：500 → 换 Key 立即重试成功
  - 开关开 + 持续 500：预算耗尽 → 503，日志含每次重试记录
  - 400/404 → 不重试直接失败
  - 流式：首字节前 500 → 重试成功
- 后端 compileall + 前端 vue-tsc + 构建
- 生产：opencode 源打开开关，高峰期观察掉线率
