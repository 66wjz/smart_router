## 一、变更背景

分组权限隔离的核心逻辑已存在（中间件注入 `key_groups` + 路由时 403/过滤双重校验），但管理体验缺失：

1. 分组写死 `free/premium` 两个选项，不可配置
2. `GET /v1/models` 返回全部上游模型，未按 API Key 分组过滤
3. 上游源/API Key 的分组下拉为静态选项，无法感知新增分组

## 二、详细设计

### 2.1 分组列表配置

- `sys_setting` 表新增配置项 `groups`（JSON：`[{name, description}]`），默认 `[{"name":"free","description":"免费分组（默认）"},{"name":"premium","description":"付费分组"}]`
- 存量数据无需迁移：未配置时读取默认值，配置后热重载生效

### 2.2 管理接口

| 接口 | 说明 |
|------|------|
| `GET /admin/api/groups` | 返回分组列表 |
| `PUT /admin/api/groups` | 整体保存分组列表（`{groups: [{name, description}]}`） |

- 分组删除限制：被上游源 `group` / API Key `groups` 引用的分组不可删，删除返回 400 并提示被引用来源
- 前端：Settings.vue 新增「分组管理」区块（表格编辑名称/描述、删除、添加、保存）；Upstreams.vue / ApiKeys.vue 的分组下拉改为从分组管理动态加载

### 2.3 /v1/models 按 Key 分组过滤

- `GET /v1/models` 读取 `request.state.key_groups`（中间件注入），遍历所有启用上游，跳过 `upstream_group not in key_groups` 的上游，再拉取其模型合并去重；别名/聚合模型条目保留
- 无 API Key 时返回 401（中间件拦截）

### 2.4 默认行为

- 未选分组的 API Key 默认 `["free"]`（现有逻辑保留）
- 新 Key 创建默认勾选 `free`

## 三、影响面

| 层 | 改动 |
|----|------|
| 后端 | `core/config.py`（get_groups/set_groups）、`services/config_service.py`（groups 透传）、`api/admin/groups.py`（新，GET/PUT + 被引用删除校验）、`api/v1/models.py`（按 key_groups 过滤上游）、`api/admin/router.py`（注册 groups_router） |
| 前端 | `api/groups.ts`（新）、`views/Settings.vue`（分组管理区块）、`views/Upstreams.vue`（分组下拉动态加载）、`views/ApiKeys.vue`（分组多选下拉动态加载 + 提示文案） |
