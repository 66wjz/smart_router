## 一、变更背景

CH-005 上线后用户反馈三个问题：

1. **模型列表过多时下滑太久**：已配置模型不折叠，需要默认折叠（可点击展开）
2. **缺少全量测试**：需要与「拉取模型」「手动添加」同行的「全量测试」按钮，一键测试全部模型
3. **测试全失败 + 失败原因不具体**：
   - 排查根因（生产日志）：生产 `newapi` 上游 `base_url` 被配置为完整 URL `https://integrate.api.nvidia.com/v1/chat/completions`，适配器再次拼接 `/v1/chat/completions` 导致请求地址变成 `/v1/chat/completions/v1/chat/completions` → **全部 404**（模型本身在 NVIDIA 官方均存在）
   - `try_non_stream`/`try_non_stream_anthropic` 所有失败路径只返回 `None`，具体错误（HTTP 状态码/响应体/超时/连接异常）被丢弃，前端只能展示固定文案

## 二、详细设计

### 2.1 后端：URL 拼接容错

- 新增 `_build_endpoint(base_url, path)` 辅助：base_url 已以目标路径结尾则直接使用，否则拼接（兼容用户误填完整 endpoint）
- 应用于：openai 非流式/流式、anthropic 非流式/流式、`fetch_upstream_models`（/v1/models）
- 生产配置修正：`newapi.base_url` → `https://integrate.api.nvidia.com`

### 2.2 后端：测试错误具体透传

- 新增测试专用函数 `test_non_stream`（openai）/ `test_non_stream_anthropic`（anthropic），返回 `(回复文本, 错误信息)`
- 错误信息具体到：`HTTP {status}: {响应体 error message}` / 连接超时 / 响应超时 / 连接异常 / 未配置 Base URL 或 Key
- `POST /upstreams/{id}/test` 改用新函数，失败返回 `{ok: false, error: "模型 xx 测试失败: <具体原因>"}`
- 主转发链路 `try_non_stream` 等保持不动（零回归风险）

### 2.3 前端：模型列表折叠

- 已配置模型超过 5 个时默认折叠（显示前 5 个），标题区出现「展开全部（n）▾」/「收起」切换

### 2.4 前端：全量测试

- 「已配置模型」头部操作行新增「全量测试」按钮（与拉取模型/手动添加同行）
- 串行逐个测试全部模型，行内实时更新状态，完成后弹窗汇总（总数/通过/失败）
- 测试中按钮显示「测试中 x/n」；开始时自动展开列表

### 2.5 前端：失败信息完整展示

- 行内失败 detail 完整展示具体原因（不再截断），红色显示，可换行
