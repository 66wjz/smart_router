> 编号：CH-020
> 日期：2026-10-16
> 分类：B 线-大（数据模型扩展 + 导航重组 + 交互修复）
> 状态：已实现 + 本地验证通过，**未部署**（上线需用户明确授权）
> 关联：CH-019（同名模型聚合、模型启停/排序、用量统计）

## 一、变更背景

CH-019 上线后暴露三个问题：

1. **只能聚同名模型**：用户实际场景是 `buddy/deepseek-v4.1-flash`、`loomy/DeepSeek-V4.1-Flash`、`trae/deepseek-v4.1-flash` —— 同一个模型，但前缀、大小写、分隔符都不同，严格字符串匹配聚不到一起。
2. **功能散落各处**：延迟探测/重试/故障转移参数在「系统设置」、智能路由概览在「仪表盘」、热重载按钮挂在顶栏全局 —— 功能复杂后，路由相关的东西到处都有。
3. **拖拽体验问题**：模型排序没有插入位置指示线；拖到其他上游源的列表会报「上游源不存在」（404）。

## 二、详细设计

### 2.1 异名模型聚合（核心）

**数据模型扩展**：`agg_model_group.upstreams` 数组的每个成员从 `{upstream, weight}` 扩展为 `{upstream, model, weight}`：

```json
[
  {"upstream": "buddy", "model": "buddy/deepseek-v4.1-flash", "weight": 1},
  {"upstream": "loomy", "model": "loomy/DeepSeek-V4.1-Flash",   "weight": 1},
  {"upstream": "trae",  "model": "trae/deepseek-v4.1-flash",    "weight": 1}
]
```

- `model` 为该源里的**真实模型名**，为空表示与聚合名同名（兼容纯同名聚合，存量数据零迁移）
- 表 `model` 字段语义从「真实模型名」升级为「**聚合名**」——客户端请求时使用的名字

**候选解析**：新增 `AppConfig.resolve_group_candidates(group_name)`，取代 direct 分支原来的 `collect_model_upstreams`：

| 场景 | 行为 |
|------|------|
| 有配置 + 启用 | 按配置的成员与顺序，每个成员携带自己的真实模型名 |
| 有配置 + 关闭 | 退化为只走第一个可用成员 |
| 无配置 | 自动发现严格同名的源（CH-019 一期行为） |

`_resolve_candidates` 的 direct 分支改为调用它，转发时用**真实模型名**请求上游。

**归一化建议**：新增 `GET /admin/api/model-groups/suggestions`

归一化规则：去 `provider/` 前缀 → 转小写 → `.` `_` 统一为 `-` → 压缩重复分隔符。

```
buddy/deepseek-v4.1-flash  ┐
loomy/DeepSeek-V4.1-Flash  ├→ deepseek-v4-1-flash
trae/deepseek-v4-flash     ┘
```

只返回满足以下条件的组：
- 分布在 **≥2 个源**
- 成员名**不完全相同**（完全同名的交给自动发现，不打扰）
- **尚未人工配置**（已合并的不再重复提示）

**新增端点**：`GET /admin/api/model-groups/source-models?upstream=xxx` —— 返回某源已配置模型，供「添加异名成员」下拉选择。

### 2.2 后台信息架构重组

侧边栏重构为四组：

```
[无分组]  仪表盘 / API Key 管理 / 上游源管理 / 模型别名
[智能路由]（折叠）
  路由规则
  聚合模型        ← 原「聚合模型名」改名
  延迟面板
  路由参数        ← 新页面，从系统设置迁入
[统计]（折叠）
  用量统计
[无分组]
  系统设置        ← 只留分组管理 + 热重载
```

**迁移明细**：

| 内容 | 原位置 | 新位置 |
|------|--------|--------|
| 延迟探测 / 请求重试 / 智能重试 / 故障转移参数 | 系统设置 | **智能路由 → 路由参数**（新页 RouteParams.vue） |
| 候选可用率、最快候选卡片 | 仪表盘 | **延迟面板**顶部 |
| 智能路由概览（规则候选可用率） | 仪表盘 | **延迟面板** →「路由规则详细状态」 |
| 模型故障 / 冷却状态 | 仪表盘 | **延迟面板** →「模型故障 / 冷却状态」 |
| 顶栏「热重载」按钮 | 全局顶栏 | 移除；保留在**路由参数**页「配置生效」区块 + 系统设置 |

仪表盘收敛为纯中转视角：上游源、API Key 两张卡片 + 上游源状态一览 + 快速操作。

### 2.3 拖拽体验修复

**问题一：无插入位置指示线**

Sortable 的 `ghostClass` 只给占位元素半透明，视觉上不明确。补充：
- ghost 元素加虚线边框 + 淡蓝底色
- `sortable-chosen`（被拖动行）加浮起阴影
- `sortable-ghost` 上加 2px 蓝色顶边，模拟插入位置线

**问题二：拖到其他源报 404「上游源不存在」**

根因两层：
1. 各上游源的 `.model-row` 使用相同的类名，Sortable 默认允许跨列表投放
2. `onEnd` 里用当前闭包变量 `u.id` 作为保存目标，但 `evt.from` / `evt.to` 可能指向另一个源 —— 于是拿 A 源的 id 去保存 B 源挪过来的模型，后端校验失败返回 404

修复：
- Sortable 配置 `group: { name: 'models-{uid}', pull: false, put: false }` —— 禁止跨列表
- `onEnd` 中比对 `evt.from` / `evt.to` 的 `data-sortable-upstream`，跨源则重新加载数据复原，不发请求
- 增加 `fallbackTolerance: 3` 提升拖拽判定的稳定性

### 2.4 顺带修正

- 顶栏版本号 v5.1 → v5.2
- 仪表盘「热重载配置」按钮改为「管理上游源」跳转
- 聚合页拖拽（编辑成员弹窗）同样加指示线与 `group` 限制
