# 变更：上游源支持多分组归属

> 编号：CH-016
> 日期：2026-08-11

> 关联：[CH-008](archived/CH-008-分组管理.md)（分组管理一期）

## 一、变更背景

分组管理一期（CH-008）中：API Key 侧已是多分组（`groups` JSON 数组，前端多选）；**上游源侧仍是单分组**（`group_name` 单值）。用户场景：同一个上游源（如 opencode go）的模型想同时给 free 和 premium 的 Key 用，目前只能二选一。

目标语义：**Key 可访问多个分组（已有）；上游源可归属多个分组（本变更）；Key 与源的分组集合有交集即可访问**。

## 二、详细设计

### 2.1 数据层

- `up_upstream` 新增 `groups` 列（text，JSON 数组字符串，如 `["free","premium"]`）
- 迁移：增量 SQL 05——加列 + 存量数据 `groups = [group_name]` 回填；`group_name` 列保留不再使用（SQLite 不好删列，逻辑废弃）
- 分组删除校验（CH-008 已有）改为检查 `groups` JSON 数组包含关系

### 2.2 权限判断语义（核心变更）

现状：`upstream.group_name not in key_groups → 拒绝`
改为：`set(upstream.groups) ∩ key_groups 为空 → 拒绝`

Key 侧 `["*"]` 通配语义不变（可访问全部）。

### 2.3 影响面

| 层 | 位置 | 改动 |
|----|------|------|
| DB | `sql/increment/05_增量_20260811_上游多分组.sql` | 加列 + 回填 |
| 后端 | `core/config.py` | `get_upstream_group` → `get_upstream_groups`（返回 set） |
| 后端 | `main.py`（allowed_groups）、`api/v1/models.py`、`services/router_service._check_group`、`core/router_engine`（候选过滤）、`core/probe` | 单值比较 → 集合交集判断（共 5 处，模式统一） |
| 后端 | `schemas/upstream.py` + `repositories/upstream_repo.py` + `services/config_service.py` | 字段 groups 读写 |
| 前端 | `Upstreams.vue` | 分组单选 → 多选；卡片展示多个分组标签 |
| 前端 | `ApiKeys.vue` | 无需改（Key 侧已多选） |

### 2.4 兼容

- 存量数据自动回填，行为不变（单分组是集合的特例）
- 热重载生效，无需重启

## 三、验证

- 本地：源配 ["free","premium"] → free Key 可调、premium Key 可调；源配 ["premium"] → free Key 403；多分组源的 /v1/models 对两类 Key 都可见
- 生产：opencode go 配双分组后，free Key 直调 mimo-v2.5 应 200
