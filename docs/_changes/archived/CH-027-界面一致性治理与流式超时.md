### 2.1 规范一：页内主操作按钮统一右上角

**基准**：`聚合模型`页（`Aggregated.vue` 使用 `<template #actions>` 挂载到 `BaseSection` 头部右侧）。

- 不再使用标题下方独立的 `<div class="toolbar">` 包裹主操作按钮。
- 同一页面若有次要操作（刷新等），与主操作同排，**刷新在左、主操作在右**。

### 2.3 规范三：按钮尺寸统一

**根因定位**：`Settings.vue` 的「热重载配置」按钮（第 121 行）**没写 `size="sm"`**，走的是 `BaseButton` 默认尺寸（`--control-height` 32px / 13px 字号），而同区块其它保存按钮写了 `size="sm"`（28px / 12px 字号）。这就是用户看到的「热重载按钮偏大」。

**规则**：
- 区块内（非弹窗、非页面主操作）的操作按钮统一 `size="sm"`。
- 弹窗底部按钮统一走 `BaseModalFooter`（内部固定 `BaseButton` 默认尺寸，保持一致）。
- 页面右上角主操作按钮统一 `size="sm"`。

**需要修的已知偏差**：
- `Settings.vue:121` 热重载按钮缺 `size="sm"`
- `Rules.vue:126/129` YAML 保存区两个按钮缺 `size="sm"`
- `ProbePlanPanel.vue:99` 「保存全局探测设置」缺 `size="sm"`
- `Rules.vue:113/114`、`Pointers.vue:86/87`、`ApiKeys.vue:98/99`、`Aggregated.vue:119/120` 弹窗底部手写按钮 → 改用 `BaseModalFooter`
- `Usage.vue:10` 刷新按钮有内联 `margin-left: 8px`（`#actions` 已自带 `gap: 8px`），属冗余

### 2.4 关于「设置页分组管理的添加按钮」

该按钮（`+ 添加分组`）语义是「在表格末尾追加一行」，与表格紧邻才符合操作预期，因此**不挪到右上角**。这与规范一不冲突：规范一约束的是「页面级新增实体」按钮。

### 2.5 规范四：侧边栏展开/收起不抖动

**根因（用户判断正确）**：`BaseSidebar.vue` 的 `.nav-item` 在展开态高度由「文字行高」撑起，收起态只剩余图标：

```css
.nav-item { padding: 8px 12px; font-size: 13px; }          /* 展开：8+行高(约18)+8 ≈ 34px */
.collapsed .nav-item { padding: 10px 0; }                  /* 收起：10+16(图标)+10 = 36px */
```

两种状态高度不同（34 vs 36），且 `.nav-group-label` 这类纯文字节点在收起时 `v-show` 直接消失，造成列表整体高度跳变。

**修正方案**：
1. 给 `.nav-item` 设定**固定高度**（展开/收起一致），不再依赖 padding + 行高相加。
2. `.nav-item-label` 设为固定行高，避免不同字符高度影响。
3. 收起态隐藏的文字节点（`nav-group-label`、`nav-sub-item` 缩进）不参与高度计算。
4. 保持宽度过渡动画（0.2s）不变。

**验收**：连续点击「收起菜单 / 展开」5 次，左侧导航项纵向位置无肉眼可见跳动，右侧内容区不发生位移。

### 2.6 规范五：流式响应头超时保护

**现状**（`openai_adapter.py:225`、`anthropic_adapter.py:210`、`responses_adapter.py:182`）：

```python
resp = await http_client.send(..., stream=True)   # 裸调用，无 wait_for
```

该行之前 `first_chunk_timeout` 尚未开始计时，之后才有 8s 首包保护。因此「等待上游返回 HTTP 响应头」这一段完全裸奔，只能等 `httpx` 全局超时兜底（`main.py:52` = `httpx.Timeout(300.0, connect=10.0)`，即 **300 秒**）。

**修正**：三处统一加 `asyncio.wait_for(..., timeout=response_timeout)`，与非流式 `try_non_stream` 完全对齐。

**行为变化边界**（明确声明，避免误判）：

| 场景 | 改前 | 改后 |
|------|------|------|
| 上游 1s 内返回响应头 | 正常 | 正常，**无变化** |
| 上游 12–20s 内返回响应头 | 正常 | 正常，**无变化** |
| 上游 60s 才返回响应头 | 卡住，客户端可能先超时 | 到 `response_timeout` 放弃该 Key，换 Key 重试 |
| 上游永不返回响应头 | 卡满 300s | 到 `response_timeout` 放弃该 Key，换 Key 重试 |
| **模型思考很久才出首字** | 受 `first_chunk_timeout` 管 | **仍受 `first_chunk_timeout` 管，不受本次影响** |

**是否可开关**：不做独立布尔开关，复用已有配置项 `retry.response_timeout`（设置页「响应超时（秒）」，默认 20）。若后续希望「完全不限制」，可作为后续独立变更讨论。

**已确认**：用户明确「关注现在这个（演示）环境就行」，因此不调整生产配置，仅改代码。

## 七、风险与回退

| 风险 | 影响 | 缓解 |
|------|------|------|
| `response_timeout` 设置过小，误杀慢启动上游 | 请求被提前放弃并换 Key | 只在「等响应头」阶段生效，`first_chunk_timeout` 独立；且换 Key 后仍有重试机会 |
| 侧边栏固定高度导致长标签被裁切 | 文字显示不全 | 标签用 `text-overflow: ellipsis`，已有；固定高度需 ≥ 单行行高 |
| 页面按钮搬家引起视觉突兀 | 用户不习惯 | 统一向「聚合模型」页看齐，该页已是用户认可形态 |

回退方式：本次为独立改动，按文件粒度 `git checkout` 即可；后端 3 处改动互不影响。
