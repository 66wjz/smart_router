## 二、组件缺陷修复

### 2.1 `ListPage` 空态不渲染分页

```diff
- <TablePagination v-if="pagination && total > 0" ... />
+ <TablePagination v-if="pagination" ... />
```

**为什么去 `total > 0`**：空列表时分页条整个消失，页面高度与「有数据时」不一致，切换筛选/清空数据时页面会跳动。用户反馈的「模型别名空的时候下面没有那个一页展示多少的条」就是这个。

保留 `total=0` 时显示「共 0 条 / 20 条/页 / ‹ 1 ›」，结构稳定。

## 四、关键决策

### 4.1 用量页三张表为什么必须拆开

原来整个用量页只有**一个外层 `ListPage`**（`pagination=false`），三张表用裸 `<h4 class="usage-sub-title">` 分隔。导致：

- 三张表共用一套「右上操作 / 工具条」，没有各自的标题栏；
- 三张表都没有分页，数据一多就整页铺开；
- 无法对某一张表单独筛选或单独翻页。

拆开后每张表 = 一个标准列表页，与 API Key 页形态一致。

### 4.2 单条维护类列表只给「批量导出」

用户拍板：模型别名、请求过滤这两处**加多选但只给批量导出，不加批量删除**。

理由：这两处的删除都是单条操作（别名改指向、规则改匹配），批量删除的误操作代价高而收益低；但「选中几条导出成 xlsx」是真实需求（比如把某几个别名发给同事核对）。

### 4.3 三张汇总表的选中策略

本地分页（数据已在内存），选中按业务键存：

| 表 | row-key |
|---|---|
| 按模型 | `model` |
| 按单元 | `upstream_id \| upstream_model` |
| 按 Key | `api_key_id` |
| 最近请求明细 | `id`（服务端分页，需 `setSelection` 同步表格勾选态） |

全选一律**只作用于当前页**（并集/差集），带半选态。

## 六、风险

| 风险 | 缓解 |
|---|---|
| 空态也显示分页，看起来「多此一举」 | 换来页面结构稳定（不随数据有无跳动）；`total=0` 时页码只有 1，视觉上很轻 |
| 用量页拆成 4 个 ListPage 后页面变长 | 每块卡片独立、留白统一，比原来裸 `<h4>` 分段更清晰；用户明确要求这个形态 |
| 三张汇总表加多选但实际很少用 | 与「批量导出」配套，且不选中时按钮置灰，不干扰阅读 |
| 服务端分页的明细表全选可能漏勾 | `toggleAllLogs` 显式调 `setSelection` 同步表格勾选态；选中按 id 存，跨页保持 |
