## 一、变更背景

上游源页面当前模型能力为**临时交互**：拉取/手动输入仅存在前端内存，刷新即丢；测试只能测"勾选的第一个模型"，无法对已配置模型逐个测试；模型不能持久化供路由规则复用。

用户确认新交互（参考 ChatBox 添加提供商后的模型管理）：

1. 每个上游源有**持久化的「已配置模型列表」**（存 DB）
2. **拉取模型**：`/v1/models` 结果面板 → 搜索/全选/勾选 → 「加入模型列表」批量写入
3. **手动添加**：头部按钮 → 弹窗输入模型名（逗号分隔）→ 添加
4. **单模型测试**：列表内每个模型单独「测试」，结果行内展示（通过/失败/耗时），失败可重试；可删除单个模型

## 二、详细设计

### 2.1 数据模型

- `up_upstream` 表新增 `models TEXT` 列（JSON 数组），默认 `[]`
- 已配置模型为上游源自身字段，路由规则候选（rules）仍独立管理

### 2.2 后端接口

| 接口 | 说明 |
|------|------|
| `PUT /admin/api/upstreams/{id}/models` | 整体写入模型列表（批量加入时前端合并去重后提交） |
| `DELETE /admin/api/upstreams/{id}/models/{model}` | 删除单个模型 |
| `GET /admin/api/upstreams` | list 返回 `models` 数组 |
| `POST /admin/api/upstreams/{id}/test` | 复用（CH-004），单模型测试 |

### 2.3 前端交互（Upstreams.vue 重构模型区块）

- 已配置模型列表：每行 = 模型名 + 状态徽标（已配置/通过 x ms/失败）+「测试」+「删除」
- 「拉取模型」按钮：展开面板（搜索 + 全选 + 勾选 chips）→「加入模型列表」→ 合并去重 → PUT 保存
- 「手动添加」按钮：BaseModal 弹窗，输入模型名逗号分隔 → 合并去重 → PUT 保存
- 行内「测试」：调用 test 接口，更新该模型行内状态，弹窗展示完整回复
