## 一、变更背景

CH-005/006 上线后用户反馈两个问题：

1. **单个模型删除删不掉**：
   - 根因：NVIDIA 模型名含 `/`（如 `01-ai/yi-large`）。前端把模型名 URL 编码后放在路径参数 `DELETE /upstreams/{id}/models/{model_name}`，但 FastAPI/Starlette 路径参数 `{model_name}` 不匹配斜杠，`%2F` 解码后路由无法匹配 → 404，删除失败
   - 修复：删除接口改走 **query 参数** `DELETE /upstreams/{id}/models?model=01-ai%2Fyi-large`（query 无路径分割歧义）
2. **缺少批量操作**：需要批量选中（全选）+ 选中后快捷「批量删除」「批量测试」

## 二、详细设计

### 2.1 后端：删除接口改 query 参数

- `DELETE /admin/api/upstreams/{upstream_id}/models?model={model_name}`（兼容含 `/` 的模型名）
- 保留原路径签名不再使用；前端同步改调用

### 2.2 前端：模型行多选 + 批量操作条

- 模型行首加 `el-checkbox` 多选；选中状态 `modelSelected[uid][model]`
- 模型列表顶部新增批量操作条：`[全选] 已选 n [批量删除] [批量测试]`（有选中时按钮可用）
- 全选 = 勾选列表全部模型（可切换）；再次点击取消全选
- 批量删除：确认后计算新列表，走已有 `PUT /upstreams/{id}/models` 整体覆盖（零新接口）
- 批量测试：复用全量测试逻辑，仅测试选中模型，逐个更新状态 + 汇总弹窗
- 单个删除同步改为 query 参数调用
