## 一、设计原则

| 维度 | 设计选择 | 理由 |
|------|---------|------|
| 配置状态源 | SQLite 数据库（内存缓存 + 热重载） | 结构化存储、并发安全，启动全量加载到内存保证路由性能 |
| 路由决策归属 | 后端引擎计算（core/router_engine） | 决策逻辑纯 Python 可单测，动态权重结合实时延迟 |
| 鉴权模型 | 两层 Key（客户端白名单 + 上游自有密钥） | 客户端密钥不透传上游，隔离安全 |
| 故障兜底 | 引擎内自动（候选重试 + 冷却 + 降级） | 无需外部编排，请求链路自愈 |
| 延迟感知 | 后台定时探测（asyncio 循环） | 实时延迟驱动动态权重，慢模型自动排除 |

## 二、核心流程图

### 流程 1：客户端智能路由（核心链路）

```mermaid
sequenceDiagram
    participant C as 客户端
    participant R as 路由代理(/v1/chat/completions)
    participant S as RouterService
    participant E as 路由引擎
    participant U as 上游API

    C->>R: POST /v1/chat/completions (带 Key)
    R->>R: API Key 白名单校验 + 注入分组
    alt Key 无效
        R-->>C: 401 (OpenAI 错误格式)
    else Key 有效
        R->>S: route_request(model, body, groups)
        alt 模型别名
            S->>S: 查找指针，替换目标模型
        else 聚合模型名
            S->>E: 规则匹配 + 候选排序 + 加权选择
            E-->>S: 选中模型 + upstream + 调整后的 max_tokens
        else 具体模型名
            S->>S: 查找模型所属上游，直接透传
        end
        S->>U: 用 upstream 自己的 Key 转发
        alt 成功
            U-->>S: 结果
            S-->>R: 成功响应
        else 失败
            S->>U: 换下一个候选模型重试
            alt 全部失败
                S-->>R: 503 无可用模型
            end
        end
        R-->>C: 返回结果
    end
```

### 流程 2：延迟探测与动态权重

```mermaid
sequenceDiagram
    participant T as 探测循环(asyncio)
    participant P as LatencyProbe
    participant C as AppConfig
    participant U as 各上游API
    participant E as 路由引擎

    T->>C: collect_probe_plan()
    C->>C: 规则候选 ∪ 别名目标 ∪ 聚合组成员
    C->>C: 按 (upstream, 真实模型) 去重<br/>多组引用取最小间隔
    C-->>T: {unit: interval, groups, sources}
    loop 每 1s tick
        T->>C: probe_plan_active(unit)?
        alt 时段外
            T->>T: 跳过，保留旧数据（标记时段外）
        else 已到期
            T->>U: 并发探测（信号量限流）
            U-->>T: 延迟/状态
            T->>T: 写回内存 data + last_check
        end
    end
    P-->>E: get_dynamic_weight / sort_group_candidates
    E->>E: 规则聚合：权重 = base × (base_latency/latency)²
    E->>E: 直接聚合：T0正常 → T1偏慢/未知 → T2 down/冷却<br/>全不可用回退配置顺序
```

> CH-021：探测单元由全局去重计划决定（聚合组只引用不拥有）；调度改为按单元到期；支持每组独立间隔与探测时段；探测失败默认不计入 Key 冷却。

### 流程 3：故障转移（冷却）

```mermaid
sequenceDiagram
    participant U as 上游API
    participant H as ModelHealth
    participant E as 路由引擎

    loop 每次请求
        U-->>H: 模型失败(HTTP错误/超时)
        H->>H: record_fail: 失败计数+1
        alt 连续失败 ≥ max_fails
            H->>H: 进入冷却期 (cooldown_seconds)
            Note over H: 冷却期内 is_available=false
            E->>E: 该模型不被选中
        else 未达阈值
            E->>E: 该模型仍可被选中
        end
        U-->>H: 模型成功
        H->>H: record_success: 清零失败计数
    end
```

### 流程 4：管理员配置热重载

```mermaid
sequenceDiagram
    participant F as Vue 管理后台
    participant A as 管理API
    participant S as ConfigService
    participant DB as SQLite

    F->>A: PUT /admin/api/rules (或其它配置接口)
    A->>S: 保存配置
    S->>DB: 写入对应表
    DB-->>S: 成功
    S->>S: 更新内存配置对象
    S-->>A: {ok: true}
    A-->>F: 保存成功
    F->>A: POST /admin/api/reload
    A->>S: 全量重载配置
    S->>DB: 读取全部配置表
    S-->>A: {ok: true, message: 配置已重新加载}
    A-->>F: 热重载成功
```

## 四、外部依赖与兜底链

### 外部依赖

| 依赖 | 用途 | 不可用影响 | 兜底方案 |
|------|------|-----------|---------|
| 上游模型提供商（NewAPI/小米） | 模型推理 | 该上游的模型全部失败 | 故障转移切换到其他候选模型 |
| 无外部数据库依赖 | SQLite 本地文件 | - | - |
| 无消息队列/调度器 | 探测用 asyncio 循环 | - | - |

### 兜底链

| 场景 | 降级链（从左到右） | 说明 |
|------|-------------------|------|
| 某候选模型失败 | 失败模型 → 同规则下一候选 → 降级候选（P3）→ 503 | get_ordered_candidates 排序后按序重试 |
| 所有候选权重为 0 | 跳过加权选择 → 返回原始候选列表 → 交给上游判定 | 避免直接 503，让真实请求裁决 |
| 全部模型不可用 | 所有候选失败 → 503 "所有模型均不可用" | 返回尝试过的模型列表 |
| 探测超时 | 该模型延迟记为超时 → down 状态 → 动态权重归 0 | 冷却恢复后自动回归 |

## 五、数据库表速览

| 表名 | 用途 | 主要字段 |
|------|------|---------|
| api_api_key | 客户端访问密钥 | name, key_value, groups, enabled |
| up_upstream | 上游模型提供商 | upstream_id, base_url, api_key, format, group_name（冗余）, groups(多分组 JSON), enabled, probe_enabled, models(JSON 对象条目), smart_retry |
| up_upstream_key | 上游 Key 池（CH-003） | upstream_id, api_key, enabled |

| rule_candidate | 规则候选模型 | rule_id, model, weight, priority, max_context, max_output |

| agg_aggregated_name | 聚合模型名 | name |
| agg_model_group | 模型聚合组（CH-019/020） | model(聚合名), upstreams(JSON: upstream/model/weight), enabled |
| agg_probe_config | 聚合组探测策略（CH-021） | model, enabled, interval_seconds, slow_threshold_seconds, sort_mode, schedule(JSON 时段) |

| sys_setting | 系统参数（含 groups 可配置分组、smart_retry 智能重试参数、latency_probe 探测参数） | key, value(JSON) |
