## 一、通用约定

| 项 | 说明 |
|----|------|
| 客户端接口 | `/v1/*`，鉴权用路由层 API Key（Bearer） |
| 管理接口 | `/admin/api/*`，鉴权用 JWT（Bearer），除 login 外全部需要 |
| 公开接口 | `/health`、`/status` 无需鉴权 |
| 管理接口成功响应 | `{"ok": true, ...}` |
| 管理接口错误响应 | HTTP 非 2xx + `{"detail": "错误描述"}` |
| 客户端错误响应 | OpenAI 格式 `{"error": {"message": ..., "type": ..., "code": ...}}`；/v1/messages 为 Anthropic 格式 `{"type":"error","error":{...}}`，/v1/responses 为 `{"error":{...}}`（CH-018 三协议错误格式统一） |

## 二、客户端接口

### 2.1 POST /v1/chat/completions

OpenAI 兼容聊天补全。model 取值三种模式：
- 聚合模型名（smart-latest/smart-chat/auto-chat）→ 智能路由
- 模型别名（如 my-model）→ 直接转发到指针目标
- 具体模型名 → 直接透传到所属上游

**鉴权**：路由层 API Key。无效返回 401，分组无权访问返回 403。

**入参**：OpenAI chat/completions 格式（model/messages/stream/max_tokens/tools）

**出参**：OpenAI chat.completion 格式（非流式）或 SSE 流（stream: true）

**错误码**：
- 401 缺失/无效 API Key
- 403 API Key 无权访问目标分组
- 503 无可用模型

### 2.2 GET /v1/models

模型列表（上游模型 + 聚合模型条目 + 别名条目）。

**鉴权**：路由层 API Key。

**分组过滤**：仅返回该 Key 有权访问分组的上游模型（无 Key 返回 401）。

**出参**：OpenAI models 列表格式。

### 2.3 GET /health

健康检查，无需鉴权。返回 `{"status": "ok", "version": "5.0"}`。

### 2.4 GET /status

实时路由状态面板，无需鉴权。

**出参**：
```json
{
  "version": "5.0",
  "aggregated_models": ["smart-latest"],
  "latency_panel": { "模型名": {"latency": "1.2s", "status": "ok", "error": null} },
  "rules": [{"name": "视觉理解", "candidates": [...]}],
  "health": {"fails": {}, "cooldown": {}}
}
```

## 三、管理接口

### 3.1 POST /admin/api/login

管理员登录。**无需鉴权**。

入参：`{ "username": "admin", "password": "xxx" }`

出参：`{ "ok": true, "token": "eyJ..." }`

错误：401 用户名或密码错误。

### 3.2 GET /admin/api/dashboard

仪表盘聚合数据。

出参：
```json
{
  "upstream_count": 2, "model_count": 12, "model_ok": 10, "model_down": 2,
  "rule_count": 3, "pointer_count": 3, "api_key_count": 3,
  "health": {"fails": {}, "cooldown": {}}
}
```

### 3.3 上游源管理

**GET /admin/api/upstreams** — 列表（密钥脱敏，含 Key 池信息）
```json
{"upstreams": [{"id": "newapi", "name": "...", "base_url": "...", "api_key": "sk-X***ow", "key_count": 3, "keys": ["sk-xxx", "sk-yyy"], "format": "openai", "group": "free", "groups": ["free"], "probe_enabled": true}]}

> `groups`：归属分组数组（CH-016 多分组，权限按集合交集判定）；`group` 为首元素冗余。
```

**POST /admin/api/upstreams** — 添加
入参：`{id, name, base_url, api_key?, api_keys?, format?, group?, probe_enabled?}`
> api_keys 为 Key 池数组（每行一个 Key，优先于 api_key）；api_key/api_keys 至少一个。
错误：400 ID 已存在。

**PUT /admin/api/upstreams/{upstream_id}** — 更新
入参：`{name?, base_url?, api_key?, api_keys?, format?, group?, probe_enabled?, enabled?}`
> 传 api_keys 则整体替换 Key 池；不传保持原 Key 池。
错误：404 不存在。

**DELETE /admin/api/upstreams/{upstream_id}** — 删除
说明：级联删除该上游的 Key 池。
错误：404 不存在。

**POST /admin/api/upstreams/{upstream_id}/test** — 测试上游源模型（CH-004）
入参：`{model, prompt?}`（prompt 默认"你好，请回复一句话"）
说明：走 Key 池选 Key，按上游 format 调 openai/anthropic 非流式转发，返回模型文本回复；失败返回具体原因（CH-006）。
响应：`{"ok": true, "content": "..."}`
错误：404 上游不存在 / 400 上游已禁用 / 502 测试失败（error 含具体原因，如 `HTTP 404 <响应体错误信息>`）。

**PUT /admin/api/upstreams/{upstream_id}/models** — 写入已配置模型列表（CH-005；CH-011 升级为对象条目）
入参：`{models: [{"name": "deepseek-chat"}, {"name": "qwen3.7-max", "protocol": "anthropic"}]}`（整体覆盖，批量加入时前端合并去重后提交；`protocol` 可选，取值 openai/anthropic/responses（CH-014），缺省继承源级 format，转发与模型测试按模型级协议分发）
响应：`{"ok": true, "models": [...]}`
错误：404 上游不存在 / 422 protocol 非法。存量纯字符串数组读取时自动归一化为对象条目。

**DELETE /admin/api/upstreams/{upstream_id}/models?model={model_name}** — 删除单个已配置模型（CH-005/CH-007）
说明：模型名走 query 参数（模型名可能含 `/`，路径参数无法匹配斜杠）。
响应：`{"ok": true}`
错误：400 model 参数缺失 / 404 上游不存在。

**PATCH /admin/api/upstreams/{upstream_id}/models?model={model_name}** — 单模型启用/禁用（CH-019）
入参：`{"enabled": false}`
说明：仅改该条目的 enabled 标记，保留 protocol；禁用后不出现在 `/v1/models`、不参与路由与探测。
响应：`{"ok": true, "model": "...", "enabled": false}`
错误：400 model 缺失 / 404 上游不存在或模型不在已配置列表。

**PUT /admin/api/upstreams/{upstream_id}/models/order** — 模型顺序重排（CH-019）
入参：`{"names": ["model-b", "model-a"]}`（重排后的完整有序名单，未出现的按原相对顺序追加尾部）
响应：`{"ok": true, "models": [...]}`
> 上游源列表（GET /admin/api/upstreams）新增 `models` 数组字段，返回该上游已配置模型。
> 上游源新增 `smart_retry` 布尔字段（CH-012，默认 false）：开启后该源请求失败（5xx/超时/连接中断）自动换 Key 或退避重试；全局参数见 GET/PUT /admin/api/config/smart-retry（extra_attempts/backoff_ms/jitter）；成功响应带 X-Served-By / X-Retry-Count 头。
> 入站协议矩阵（2026-08-11 收齐）：`POST /v1/chat/completions`（OpenAI）、`POST /v1/messages`（Anthropic 格式入站，鉴权兼容 x-api-key 头，CH-009）、`POST /v1/responses`（Responses 格式入站，Codex 可用，CH-010）。三者入参/出参各自遵循对应协议格式，内部统一归一化为 openai chat 后走同一路由引擎，分组权限/Key 池/智能重试/出站协议分发全链路一致生效。
> CH-018（2026-08-12）：三入站错误统一为各协议标准格式（OpenAI `{"error":{...}}` / Anthropic `{"type":"error","error":{...}}` / Responses `{"error":{...}}`），客户端 SDK 可直接解析；messages/responses 入站补图片块映射（anthropic `image` / responses `input_image` → openai `image_url`），发图真实透传；推理模型 `reasoning` 内容映射（anthropic `thinking` 块/`thinking_delta`、responses `reasoning` item/`reasoning_summary_text.delta`），正文为空时推理内容不丢失。

### 3.6 API Key 管理

**GET /admin/api/api-keys** — 列表

{"api_keys": [{"name": "默认 Key", "key": "sk-...", "key_masked": "sk-s***ault", "enabled": true, "groups": ["free"]}]}

### 3.7 聚合模型名

**GET /admin/api/aggregated-names** — `{"names": ["smart-latest", ...]}`
**PUT /admin/api/aggregated-names** — 入参 `{names: [...]}`

### 3.7.1 同名模型聚合组（CH-019）

**GET /admin/api/model-groups** — 同名多源模型列表（可选 `?model=xxx`）
```json
{"groups": [{"model": "deepseek-v4-flash", "sources": ["dsh", "trae"], "enabled": true, "configured": false, "auto_sources": ["dsh", "trae"]}]}
```
> `sources` = 当前生效顺序；`configured=false` 表示走自动发现；`auto_sources` = 自动发现的全部可用源。
> 只返回分布在 ≥2 个源的模型；人工配置过的模型即使只剩 1 个源也返回。

**PUT /admin/api/model-groups?model={model_name}** — 保存人工配置
入参：`{"upstreams": [{"upstream": "dsh", "weight": 1}, {"upstream": "trae", "weight": 1}], "enabled": true}`
> 数组顺序即候选优先级；`enabled=false` 表示关闭聚合、退化为首个可用源直连。
错误：400 model 缺失 / 404 上游源不存在 / 422 upstreams 为空。

**DELETE /admin/api/model-groups?model={model_name}** — 删除人工配置，回到自动发现

### 3.7.2 用量统计（CH-019）

**GET /admin/api/usage/summary?range=today|7d|30d** — 全局汇总
```json
{"total": 128, "success_count": 125, "success_rate": 0.9766, "total_tokens": 456789, "active_keys": 3, "top_errors": [{"target": "dsh/deepseek-v4-flash", "count": 2}]}
```

**GET /admin/api/usage/by-model?range=...** — `{"models": [{model, requests, success_count, error_count, prompt_tokens, completion_tokens, total_tokens, avg_duration_ms, upstream_count}]}`

**GET /admin/api/usage/by-key?range=...** — `{"keys": [{api_key_id, api_key_name, requests, success_count, error_count, total_tokens, avg_duration_ms}]}`

**GET /admin/api/usage/logs?range=...&page=1&size=50&key_id=&model=&status=success|error** — `{"total", "page", "size", "items": [...log_usage 行...]}`

**POST /admin/api/usage/flush** — 手动把内存缓冲落库（调试用）

> 用量采集说明：非流式直接取上游 `usage`；流式对 openai 兼容上游注入 `stream_options.include_usage` 并解析末 chunk（客户端未要求时剥离该 chunk）；上游不支持时按字符估算并置 `estimated=1`；失败请求同样记录（`status=error`）。

### 3.8 系统参数

**GET/PUT /admin/api/config/probe** — 延迟探测配置
字段：enabled/interval_seconds/timeout_seconds/request_text/max_tokens/base_latency/down_threshold_seconds/slow_threshold_seconds/error_as_down

**GET/PUT /admin/api/config/retry** — 重试配置
字段：max_attempts/response_timeout/first_chunk_timeout

**GET/PUT /admin/api/config/failover** — 故障转移配置
字段：max_fails/cooldown_seconds

### 3.9 PUT /admin/api/admin-password

修改管理员密码。

入参：`{old_password, new_password}`（新密码至少 6 位）
错误：400 当前密码错误。

### 3.10 POST /admin/api/reload

热重载配置（从数据库重新加载到内存）。

出参：`{"ok": true, "message": "配置已重新加载"}`

### 3.11 GET /admin/api/groups

分组列表（Settings 页「分组管理」区块加载用）。

出参：`{"groups": [{"name": "free", "description": "免费分组（默认）"}, {"name": "premium", "description": "付费分组"}]}`

### 3.12 PUT /admin/api/groups

整体保存分组列表。

入参：`{"groups": [{"name": "free", "description": "..."}]}`（整体覆盖）

错误：400 被上游源或 API Key 引用的分组不可删除。
