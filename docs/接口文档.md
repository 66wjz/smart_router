## 一、通用约定

| 项 | 说明 |
|----|------|
| 客户端接口 | `/v1/*`，鉴权用路由层 API Key（Bearer） |
| 管理接口 | `/admin/api/*`，鉴权用 JWT（Bearer），除 login 外全部需要 |
| 公开接口 | `/health`、`/status` 无需鉴权 |
| 管理接口成功响应 | `{"ok": true, ...}` |
| 管理接口错误响应 | HTTP 非 2xx + `{"detail": "错误描述"}` |
| 客户端错误响应 | OpenAI 格式 `{"error": {"message": ..., "type": ..., "code": ...}}`；/v1/messages 为 Anthropic 格式 `{"type":"error","error":{...}}`，/v1/responses 为 `{"error":{...}}`（CH-018 三协议错误格式统一） |

## 二、客户端接口

### 2.1 POST /v1/chat/completions

OpenAI 兼容聊天补全。model 取值三种模式：
- 聚合模型名（smart-latest/smart-chat/auto-chat）→ 智能路由
- 模型别名（如 my-model）→ 直接转发到指针目标
- 具体模型名 → 直接透传到所属上游

**鉴权**：路由层 API Key。无效返回 401，分组无权访问返回 403。

**入参**：OpenAI chat/completions 格式（model/messages/stream/max_tokens/tools）

**角色兼容（CH-037）**：`messages[].role` 支持 `system` / `developer` / `user` / `assistant` / `tool`。网关在**出站转发前**会把 `developer` 自动改写为 `system`（OpenAI 规范中二者语义等价），以兼容只认 `system` 的上游；其余角色原样透传，消息内容与顺序不变。

**出参**：OpenAI chat.completion 格式（非流式）或 SSE 流（stream: true）

**错误码**：
- 400 请求体不是合法 JSON / 不是 JSON 对象 / model 缺失 / messages 缺失或不是数组（CH-025）
- 401 缺失/无效 API Key
- 403 API Key 无权访问目标分组
- 503 无可用模型
- 500 服务端未捕获异常（CH-025：按 OpenAI 格式返回 `{"error":{"message":"中转站内部错误: <类型>",...}}`，不再是纯文本）

### 2.2 GET /v1/models

模型列表（上游模型 + 聚合模型条目 + 别名条目）。

**鉴权**：路由层 API Key。

**分组过滤**：仅返回该 Key 有权访问分组的上游模型（无 Key 返回 401）。

**出参**：OpenAI models 列表格式。

**CH-033**：聚合条目覆盖 rule 与 static 两类（此前只输出 rule，导致异名/固定成员聚合在列表里看不到）。聚合条目带 `type: "aggregation"`，`aggregation_kind` 区分 `rule` / `static`（static 另带 `member_count`）；`enabled=false` 的聚合不输出；重名时只输出一次。

**CH-034**：聚合条目按**聚合自身 `groups`** 过滤（空 = 所有 Key 可见），不再按成员所属上游源分组过滤；真实模型条目仍按上游源分组过滤。聚合条目额外输出 `groups`。被拒时聚合报 `无权访问聚合 xxx`，真实模型报 `无权访问分组 [...]（模型 xxx）`。

### 2.3 GET /health

健康检查，无需鉴权。返回 `{"status": "ok", "version": "5.0"}`。

### 2.4 GET /status

实时路由状态面板，无需鉴权。

**出参**：
```json
{
  "version": "5.0",
  "aggregated_models": ["smart-latest"],
  "latency_panel": { "模型名": {"latency": "1.2s", "status": "ok", "error": null} },
  "rules": [{"name": "视觉理解", "candidates": [...]}],
  "health": {"fails": {}, "cooldown": {}}
}
```

## 三、管理接口

### 3.1 POST /admin/api/login

管理员登录。**无需鉴权**。

入参：`{ "username": "admin", "password": "xxx" }`

出参：`{ "ok": true, "token": "eyJ..." }`

错误：401 用户名或密码错误。

### 3.2 GET /admin/api/dashboard

仪表盘聚合数据（CH-022 扩展为完整首页）。

出参（节选）：
```json
{
  "upstream_count": 4, "model_count": 12, "probe_unit_count": 7,
  "model_ok": 5, "model_down": 2,
  "rule_count": 3, "pointer_count": 3, "api_key_count": 3,
  "health": {"fails": {}, "cooldown": {}, "probe_down": {}},

  "usage_today": {"requests": 56, "success_rate": 0.946, "total_tokens": 63800,
                  "active_keys": 3, "requests_delta": -0.45},
  "usage_7d": {"requests": 724, "total_tokens": 771800, "success_rate": 0.981},
  "trend": [{"date": "10-11", "requests": 82, "success_count": 81, "total_tokens": 91600}],

  "upstream_usage": [{"upstream_id": "buddy", "upstream_name": "Buddy 积分池",
                      "requests": 327, "error_count": 7, "total_tokens": 376600,
                      "share": 0.488, "probe_ok": 3, "probe_total": 3,
                      "enabled": true, "smart_retry": true}],
  "groups": [{"model": "deepseek-v4-1-flash", "member_count": 3, "members": [...],
              "configured": true, "probe_enabled": true, "probe_interval": 60,
              "probe_schedule": "工作日 08:00-23:00", "probe_schedule_mode": "window",
              "sort_mode": "latency", "requests_7d": 297, "tokens_7d": 268700}],
  "attention": [{"kind": "probe_down", "target": "gemini-2.5-pro@buddy", "detail": "..."}],
  "probe_summary": {"enabled": true, "unit_count": 7, "ok": 5, "down": 1, "unknown": 1,
                    "global_interval": 300, "global_schedule": "全天候", "scheduled_off": 3}
}
```

说明：
- `usage_today` / `trend` 均按请求时间 `ts` 计算（today 从本地自然日 0 点起）；`requests_delta` 为「今日至今 vs 昨日同期」环比
- `trend` 固定返回最近 7 个自然日，无数据的日期补 0
- `upstream_usage.share` 按 tokens 占比；`probe_ok/probe_total` 为该源当前探测可用率
- `groups` 来自聚合组快照；`configured=false` 表示自动发现（未手动编辑过）
- `attention.kind`：`cooldown` / `probe_down` / `no_key` / `stale` / `disabled_upstream`
- `log_usage` 表不存在时，用量相关字段返回零值，其余字段不受影响

### 3.3 上游源管理

**GET /admin/api/upstreams** — 列表（密钥脱敏，含 Key 池信息）
```json
{"upstreams": [{"id": "newapi", "name": "...", "base_url": "...", "api_key": "sk-X***ow", "key_count": 3, "keys": ["sk-xxx", "sk-yyy"], "format": "openai", "group": "free", "groups": ["free"], "probe_enabled": true}]}

> `groups`：归属分组数组（CH-016 多分组，权限按集合交集判定）；`group` 为首元素冗余。
```

**POST /admin/api/upstreams** — 添加
入参：`{id, name, base_url, api_key?, api_keys?, format?, group?, probe_enabled?}`
> api_keys 为 Key 池数组（每行一个 Key，优先于 api_key）；api_key/api_keys 至少一个。
错误：400 ID 已存在。

**PUT /admin/api/upstreams/{upstream_id}** — 更新
入参：`{name?, base_url?, api_key?, api_keys?, format?, group?, probe_enabled?, enabled?}`
> 传 api_keys 则整体替换 Key 池；不传保持原 Key 池。
错误：404 不存在。

**DELETE /admin/api/upstreams/{upstream_id}** — 删除
说明：级联删除该上游的 Key 池。
错误：404 不存在。

**POST /admin/api/upstreams/{upstream_id}/test** — 测试上游源模型（CH-004）
入参：`{model, prompt?}`（prompt 默认"你好，请回复一句话"）
说明：走 Key 池选 Key，按上游 format 调 openai/anthropic 非流式转发，返回模型文本回复；失败返回具体原因（CH-006）。
响应：`{"ok": true, "content": "..."}`
错误：404 上游不存在 / 400 上游已禁用 / 502 测试失败（error 含具体原因，如 `HTTP 404 <响应体错误信息>`）。

**PUT /admin/api/upstreams/{upstream_id}/models** — 写入已配置模型列表（CH-005；CH-011 升级为对象条目）
入参：`{models: [{"name": "deepseek-chat"}, {"name": "qwen3.7-max", "protocol": "anthropic"}]}`（整体覆盖，批量加入时前端合并去重后提交；`protocol` 可选，取值 openai/anthropic/responses（CH-014），缺省继承源级 format，转发与模型测试按模型级协议分发）
响应：`{"ok": true, "models": [...]}`
错误：404 上游不存在 / 422 protocol 非法。存量纯字符串数组读取时自动归一化为对象条目。

**DELETE /admin/api/upstreams/{upstream_id}/models?model={model_name}** — 删除单个已配置模型（CH-005/CH-007）
说明：模型名走 query 参数（模型名可能含 `/`，路径参数无法匹配斜杠）。
响应：`{"ok": true}`
错误：400 model 参数缺失 / 404 上游不存在。

**PATCH /admin/api/upstreams/{upstream_id}/models?model={model_name}** — 单模型启用/禁用（CH-019）
入参：`{"enabled": false}`
说明：仅改该条目的 enabled 标记，保留 protocol；禁用后不出现在 `/v1/models`、不参与路由与探测。
响应：`{"ok": true, "model": "...", "enabled": false}`
错误：400 model 缺失 / 404 上游不存在或模型不在已配置列表。

**PUT /admin/api/upstreams/{upstream_id}/models/order** — 模型顺序重排（CH-019）
入参：`{"names": ["model-b", "model-a"]}`（重排后的完整有序名单，未出现的按原相对顺序追加尾部）
响应：`{"ok": true, "models": [...]}`
> 上游源列表（GET /admin/api/upstreams）新增 `models` 数组字段，返回该上游已配置模型。
> 上游源新增 `smart_retry` 布尔字段（CH-012，默认 false）：开启后该源请求失败（5xx/超时/连接中断）自动换 Key 或退避重试；全局参数见 GET/PUT /admin/api/config/smart-retry（extra_attempts/backoff_ms/jitter）；成功响应带 X-Served-By / X-Retry-Count 头。
> 入站协议矩阵（2026-08-11 收齐）：`POST /v1/chat/completions`（OpenAI）、`POST /v1/messages`（Anthropic 格式入站，鉴权兼容 x-api-key 头，CH-009）、`POST /v1/responses`（Responses 格式入站，Codex 可用，CH-010）。三者入参/出参各自遵循对应协议格式，内部统一归一化为 openai chat 后走同一路由引擎，分组权限/Key 池/智能重试/出站协议分发全链路一致生效。
> CH-018（2026-08-12）：三入站错误统一为各协议标准格式（OpenAI `{"error":{...}}` / Anthropic `{"type":"error","error":{...}}` / Responses `{"error":{...}}`），客户端 SDK 可直接解析；messages/responses 入站补图片块映射（anthropic `image` / responses `input_image` → openai `image_url`），发图真实透传；推理模型 `reasoning` 内容映射（anthropic `thinking` 块/`thinking_delta`、responses `reasoning` item/`reasoning_summary_text.delta`），正文为空时推理内容不丢失。

### 3.7.1 模型聚合组（CH-019 / CH-020）

**GET /admin/api/model-groups** — 聚合组列表（可选 `?model=xxx`）
```json
{"groups": [{
  "model": "deepseek-v4-1-flash",
  "sources": ["buddy", "loomy", "trae"],
  "members": [
    {"upstream": "buddy", "model": "buddy/deepseek-v4.1-flash"},
    {"upstream": "loomy", "model": "loomy/DeepSeek-V4.1-Flash"},
    {"upstream": "trae",  "model": "trae/deepseek-v4.1-flash"}
  ],
  "enabled": true, "configured": true, "auto_sources": []
}]}
```
> `model` = 聚合名；`members[].model` = 该源里的真实模型名（支持异名）；`configured=false` 表示自动发现。
> 自动发现只返回严格同名且跨 ≥2 源的模型；人工配置的始终返回。

**PUT /admin/api/model-groups?model={model_name}** — 保存聚合配置
入参：`{"upstreams": [{"upstream": "buddy", "model": "buddy/deepseek-v4.1-flash", "weight": 1}], "enabled": true}`
> `upstreams[].model` 可省略，省略表示与聚合名同名；数组顺序即优先级；`enabled=false` 表示关闭聚合。
错误：400 model 缺失 / 404 上游源不存在 / 422 upstreams 为空。

**DELETE /admin/api/model-groups?model={model_name}** — 删除人工配置，回到自动发现

**GET /admin/api/model-groups/suggestions** — 异名聚合建议（CH-020）
按「去 `provider/` 前缀 → 转小写 → `.` `_` 视为 `-`」归一化，聚类出疑似同一模型。
```json
{"suggestions": [{"suggested_name": "deepseek-v4-1-flash", "normalized": "deepseek-v4-1-flash",
  "members": [{"upstream": "buddy", "upstream_name": "Buddy 池", "model": "buddy/deepseek-v4.1-flash"}]}]}
```
> 只返回跨 ≥2 源、成员名不完全相同、尚未人工配置的分组；前端「一键合并」直接拿 `members` 调 PUT。

**GET /admin/api/model-groups/source-models?upstream={id}** — 某源已配置模型（添加异名成员时下拉用）
```json
{"upstream": "buddy", "models": [{"name": "buddy/deepseek-v4.1-flash", "enabled": true}]}
```

**GET /admin/api/model-groups/probe-configs** — 所有聚合组的探测配置（CH-021）
```json
{"configs": {"deepseek-v4-1-flash": {"model": "...", "configured": true, "enabled": true,
  "interval_seconds": 30, "slow_threshold_seconds": 4, "sort_mode": "latency",
  "schedule": {"mode": "window", "days": [1,2,3,4,5], "windows": [{"start":"08:00","end":"23:00"}]},
  "member_count": 3, "raw": {"...落库原值..."}}}}
```
`configured=false` 表示无人工配置，各字段为全局继承值。

**PUT /admin/api/model-groups/probe?model={name}** — 保存组探测配置（CH-021）
```json
{"enabled": true, "interval_seconds": 30, "slow_threshold_seconds": 4, "sort_mode": "stable|latency",
 "schedule": {"mode": "always|window", "days": [1..7], "windows": [{"start":"08:00","end":"23:00"}]}}
```
`interval_seconds` / `slow_threshold_seconds` 传 `0` 或 `null` = 跟随全局。校验失败 422；组不存在 404。

**DELETE /admin/api/model-groups/probe?model={name}** — 恢复默认（不探测）

**GET /admin/api/model-groups/probe-plan** — 全局去重探测计划（CH-021 / CH-023，推荐改用 `GET /admin/api/probe-plan`）
```json
{"summary": {"unit_count": 12, "member_refs": 16, "dedup_saved": 4, "daily_requests": 17280,
             "global_interval": 360, "aggregation_count": 8},
 "units": [{"key": "buddy:deepseek-v4.1-flash", "upstream": "buddy", "upstream_name": "Buddy",
   "model": "deepseek-v4.1-flash", "groups": ["deepseek-v4-1-flash", "smart-latest"],
   "group_kinds": {"deepseek-v4-1-flash": "static", "smart-latest": "rule"},
   "sources": ["group"],
   "schedule": {"mode": "window", "days": [1,2,3,4,5], "windows": [{"start":"08:00","end":"23:00"}]},
   "schedules": [{"mode": "window", "...": "..."}],
   "interval": 60, "latency": 1.2, "status": "ok", "last_check": 1792228899,
   "stale": false, "active_now": true}]}
```
探测单元 = (上游源, 真实模型名)，全局唯一；多聚合引用同一单元时 `interval` 取最小值；`daily_requests = Σ(86400/interval)`；`groups` 含 rule 聚合（探测对象为规则候选并集），`group_kinds` 区分类型；`active_now=false` 表示当前处于探测时段外（多引用方取时段并集）；`stale=true` 表示超过 `3×interval` 未更新。

### 3.7.3 统一聚合（CH-023）

**GET /admin/api/aggregations** — 统一聚合列表
```json
{"aggregations": [{
  "name": "deepseek-v4-1-flash", "kind": "static", "enabled": true, "configured": true,
  "members": [{"upstream": "buddy", "model": "deepseek-v4.1-flash", "weight": 3}],
  "groups": ["premium"],
  "member_count": 3, "template_id": 1, "template_name": "高频-交易时段",
  "probe": {"enabled": true, "interval_seconds": 60, "slow_threshold_seconds": 5,
            "sort_mode": "latency", "schedule": {"mode": "window"},
            "template_id": 1, "template_name": "高频-交易时段"},
  "self_config": {"probe_enabled": true, "interval_seconds": 60, "slow_threshold_seconds": 5.0,
                  "sort_mode": "latency", "schedule": {}},
  "remark": ""
}, {
  "name": "smart-latest", "kind": "rule", "members": [], "member_count": 7,
  "rule_names": ["默认对话", "视觉理解"],
  "rule_bindings": [{"rule": "默认对话", "candidates": null},
                    {"rule": "视觉理解", "candidates": [{"upstream": "buddy", "model": "gemini-2.5-pro"}]}],
  "rule_binding_summary": {"rule_count": 2, "candidate_count": 3,
    "items": [{"rule": "默认对话", "count": 2, "follow_all": true},
              {"rule": "视觉理解", "count": 1, "follow_all": false}]},
  "stale_bindings": []
}]}
```
> `probe` = 生效值（模板优先 → 自配 → 全局）；`self_config` = 落库原值（编辑回显）；`configured=false` = 同名自动发现；`kind=rule` 的 `members` 恒空、`member_count` 为按绑定裁剪后的单元数。
> CH-024：`rule_bindings` = `null`/`[]` 全跟随，或 `[{"rule","candidates"}]`（`candidates=null` 该规则全跟随，数组为显式候选子集）；`rule_binding_summary` 供卡片摘要；`stale_bindings` 为失效项（`rule_missing` / `candidate_missing`）。
> CH-034：`groups` = 聚合自身可用分组，空数组 = 所有 Key 可用。static 与 rule 同一语义；成员所属上游源分组不参与聚合权限判断（只影响直接请求真实模型名的场景）。

**PUT /admin/api/aggregations?name={name}** — 新建/更新
入参：`{"kind":"static|rule","members":[...],"rule_bindings":[...],"groups":["premium"],"enabled":true,"probe_enabled":true,"template_id":1,"sort_mode":"stable|latency","interval_seconds":60,"slow_threshold_seconds":5,"schedule":{...},"remark":""}`
> 均可选，未提供保持原值；`template_id` / `interval_seconds` / `slow_threshold_seconds` / `rule_bindings` / `groups` 支持**显式 `null` 清空**；`kind=rule` 不允许传成员。
> CH-024 校验：`rule_bindings[].rule` 不存在 → 404；`candidates` 项不属于该规则 → 400；规则候选为空 → 400。
> CH-034 校验：`groups` 里的分组名必须存在于分组表，否则 404。
> 错误：400 name/kind 缺失或 rule 传成员；404 上游源/模板/规则/分组不存在；422 参数非法。

**DELETE /admin/api/aggregations?name={name}** — 删除；404 不存在。

**PUT /admin/api/aggregations/order** — 保存聚合列表的人工拖拽顺序（CH-028）
入参：`{"names":["deepseek-v4-1-flash","smart-chat"]}`，出参：`{"ok":true,"count":2}`。
> 顺序存 `sys_setting.aggregation_order`，不改表结构；数组里不存在的名字被过滤；未列入的聚合（新增/自动发现）排在末尾；传空数组恢复默认（`kind+name`）顺序。

**GET /admin/api/aggregations/rule-units?name={name}** — rule 聚合的探测对象（候选并集，已展开为真实模型名）；传 `name` 返回该聚合按 `rule_bindings` 裁剪后的结果，不传为全部规则并集（旧行为）。出参含 `aggregation` 字段回显查询名。

### 3.7.4 探测模板（CH-023）

**GET /admin/api/probe-templates** — `{"templates":[{"id","name","interval_seconds","slow_threshold_seconds","sort_mode","schedule","remark","ref_count","ref_names"}]}`
**POST /admin/api/probe-templates** — 新建（`name` 唯一）
**PUT /admin/api/probe-templates/{id}** — 更新
**DELETE /admin/api/probe-templates/{id}** — 删除，返回 `{"ok":true,"id":x,"affected":["聚合名"]}`；引用方 `template_id` 置空并回退自配 → 全局
> 校验：`interval_seconds ≥ 10`；`slow_threshold_seconds` 为 `null`/`0` 表示跟随全局，否则 ≥ 1；`sort_mode ∈ {stable, latency}`。

### 3.7.5 请求过滤规则（CH-041）

转发前拦截：命中规则的候选**不会发往上游**，避免触发上游渠道按请求内容维护的客户端黑名单（如 WorkBuddy 拦 DSH / Claude Code）。

**GET /admin/api/filter-rules** — `{"enabled": false, "rules": [{id, name, enabled, target, pattern, upstream_ids, action, remark}], "targets": [...], "actions": [...]}`
**POST /admin/api/filter-rules** — 新建（`name` 唯一、`pattern` 非空）
**PUT /admin/api/filter-rules/{id}** — 更新
**DELETE /admin/api/filter-rules/{id}** — 删除
**PUT /admin/api/filter-rules/engine** — `{"enabled": true|false}`，全局开关（默认 `false`）
**POST /admin/api/filter-rules/test** — 试跑：`{"body": {...}, "upstream_ids": [...]}` → `{"engine_enabled", "matched", "results": [{upstream, rules: [{id, name, action}]}], "enabled_rule_count"}`

> `target ∈ {system_first_line, system_any, body_regex}`；`action ∈ {skip, reject}`；`upstream_ids` 为空 = 作用于全部上游源。
> 匹配用「字面包含」而非「完全相等」——漏拦的代价是消耗一次上游调用，误拦只是跳过一个源。
> **运行时**：聚合命中 → 静默换成员（200）；聚合全命中 → 503；单模型直连命中 → **400**；引擎关闭/未命中 → 行为完全不变。
> 被拦截请求写 `log_usage`，`error_msg` 前缀 `【已过滤】`，尝试链记 `http_status=null`。

### 3.7.2 用量统计（CH-019）

**GET /admin/api/usage/summary?range=today|7d|30d** — 全局汇总
```json
{"total": 128, "success_count": 125, "success_rate": 0.9766, "total_tokens": 456789, "active_keys": 3, "filtered_count": 4, "top_errors": [{"target": "dsh/deepseek-v4-flash", "count": 2}]}
```
> `filtered_count`（CH-041）：被请求过滤引擎拦截、未发往上游的请求数。

**GET /admin/api/usage/by-model?range=...** — `{"models": [{model, requests, success_count, error_count, prompt_tokens, completion_tokens, total_tokens, avg_duration_ms, upstream_count}]}`

**GET /admin/api/usage/by-key?range=...** — `{"keys": [{api_key_id, api_key_name, requests, success_count, error_count, total_tokens, avg_duration_ms}]}`

**GET /admin/api/usage/by-unit?range=...** — 按「上游源 × 上游真实模型名」聚合（CH-021，号池核算）
```json
{"units": [{"upstream_id": "buddy", "upstream_name": "Buddy", "upstream_model": "deepseek-v4.1-flash",
  "requests": 320, "success_count": 318, "error_count": 2, "request_models": 3,
  "prompt_tokens": 900000, "completion_tokens": 350000, "total_tokens": 1250000,
  "avg_duration_ms": 2100, "last_ts": 1792228899}]}
```
`upstream_model` 取 `COALESCE(upstream_model, model)`：CH-021 之前的老数据回退用请求名。`request_models` = 该单元被多少个不同客户端请求名命中。

**GET /admin/api/usage/logs?range=...&page=1&size=50&key_id=&model=&status=success|error** — `{"total", "page", "size", "items": [...log_usage 行...]}`
CH-038：每行补 `cache_read_tokens` / `cache_write_tokens` / `attempt_count`（旧库缺列给 0/0/1），原有字段全部保留。

**GET /admin/api/usage/logs/{log_id}** — 单条请求详情（CH-038）
返回 `{id, summary, attempts, detail}`：
- `summary`：主表整行（含 `cache_*` / `attempt_count` / `http_status`，499 = 客户端断开）
- `attempts`：尝试链 `[{upstream, model, http_status, ms, error}]`，长度等于 `attempt_count`
- `detail`：`{available, request_headers, request_body, forward_body, response_body, truncated}`；`available=false` 时带 `reason`
  - `request_body` = 客户端原始请求；`forward_body` = **实际发给上游的报文**（能直接看出模型替换、`developer→system` 等改写）；`response_body` = 上游响应（流式只存首尾各 20 条片段）
  - 报文超 `usage_detail_max_bytes` 时按头 3/4 + 尾 1/4 截断，`truncated` 标记具体哪一栏
  - 报文落库前已脱敏（`sk-xxxx` → `sk-xxxx****`），请求头仅保留 user-agent / content-type / accept / accept-encoding
- `log_id` 不存在 → 404

**GET/PUT /admin/api/config/usage-detail** — 详情采集与保留策略（CH-038）
- GET → `{mode, max_bytes, retention_days}`（默认 `error_only` / `1048576` / `14`）
- PUT 入参同上；`mode ∈ off|error_only|all`，`max_bytes ∈ 1024~1048576`，`retention_days ∈ 1~3650`（UI 给 7/14/30/90）；非法值 → 422
- 保留期对**主表与详情表同时生效**，后台每小时清理一次，先删详情再删主表

**POST /admin/api/usage/flush** — 手动把内存缓冲落库（调试用）

> 用量采集说明：非流式直接取上游 `usage`；流式对 openai 兼容上游注入 `stream_options.include_usage` 并解析末 chunk（客户端未要求时剥离该 chunk）；上游不支持时按字符估算并置 `estimated=1`；失败请求同样记录（`status=error`）。
> 缓存 token（CH-038）兼容三种命名：`prompt_tokens_details.cached_tokens` / `cache_read_input_tokens` + `cache_creation_input_tokens` / `prompt_cache_hit_tokens` + `prompt_cache_miss_tokens`；都取不到则记 0，**不估算**。

### 3.8 系统参数

**GET/PUT /admin/api/config/probe** — 延迟探测配置
字段：enabled/interval_seconds/timeout_seconds/request_text/max_tokens/base_latency/down_threshold_seconds/slow_threshold_seconds/error_as_down
CH-021 新增：`max_concurrency`（并发上限，默认 5）、`count_key_failures`（探测失败是否计入 Key 冷却，默认 false）、`schedule`（全局探测时段，作用于规则/别名命中的单元）

**GET/PUT /admin/api/config/retry** — 重试配置
字段：max_attempts/response_timeout/first_chunk_timeout

**GET/PUT /admin/api/config/smart-retry** — 智能重试全局参数（CH-012）
字段：`extra_attempts`（额外尝试次数，默认 2）、`backoff_ms`（同 Key 退避毫秒序列，默认 `[500,1500]`）、`jitter`（抖动比例，默认 0.2）
> 只对开启 `smart_retry` 的上游源生效；开启后 5xx 纳入可重试，同 Key 重试前按退避序列 + 抖动等待。存 `sys_setting.smart_retry`。

**GET/PUT /admin/api/config/failover** — 故障转移配置
字段：max_fails/cooldown_seconds

**GET/PUT /admin/api/config/auto-aggregate** — 同名模型自动聚合开关（CH-036）
字段：`{ "enabled": false }`（默认关闭）
> 关闭时同名模型只做跨源兜底（仍返回多候选），不出现在聚合列表、不作为聚合参与权限判断；打开则恢复 CH-019 行为（同名分布 ≥2 个启用源自动成为聚合组）。存 `sys_setting.auto_same_name_aggregate`。

### 3.13 GET /admin/api/logs（CH-025）

读取服务端轮转日志尾部，不登录服务器也能拿到出错现场。

**参数**：`lines`（默认 200，上限 5000）、`keyword`（非空时只返回含该子串的行）

**出参**：`{"ok": true, "file": "...", "size_bytes": 33819, "returned": 3, "keyword": "", "content": "..."}`

**日志行格式**（`access` logger）：

```
2026-10-18 12:48:51 [WARNING] access: POST /v1/chat/completions status=400 elapsed=0.00s client=127.0.0.1 model=deepseek-v4-1-flash stream=False messages=1 | body_snippet={"model":"...","messages":[...]}
```

- `body=INVALID(empty|bad_json|not_object)` 表示请求体无法解析
- `body_snippet` 截断 300 字符，`sk-xxx` 已脱敏为 `sk-abcd****`
- 文件策略：单文件 10MB × 保留 5 份，目录可用 `SMART_ROUTER_LOG_DIR` 覆盖

### 3.15 数据导出（CH-042）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/admin/api/export/datasets` | 可用数据集清单 `{datasets: [...]}`（须声明在 `/export/{dataset}` 之前，否则被通配吃掉） |
| GET | `/admin/api/export/{dataset}` | 导出全部（受 query 筛选约束），返回 xlsx 二进制流 |
| POST | `/admin/api/export/{dataset}` | 批量导出选中项，body `{"ids": ["..."]}`，ids 为空返回 400 |

- 响应头：`Content-Type: application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`、`Content-Disposition`（`filename*` 按 RFC 5987 编码，中文名不乱码）、`Access-Control-Expose-Headers: Content-Disposition`（前端 axios 靠它拿真实文件名）
- 未知 dataset → 404
- 数据集：`pointers` / `api-keys` / `filter-rules` / `usage-by-model` / `usage-by-unit` / `usage-by-key` / `usage-logs` / `groups` / `probe-templates` / `probe-units`（各集成的筛选参数见 `docs/API契约.md` 4.24）
